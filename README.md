# QuizForge Web 第一版

本机／局域网浏览器界面，Java 后端保存数据。独立目录实现，不修改 QuizForge V2。

## 启动

运行需要 JDK 21+ 和 Node.js 24；首次构建或重建还需要 Maven。双击 `Start-QuizForge-Web.cmd`，或在本目录运行：

```powershell
.\Start-QuizForge-Web.cmd
```

首次自动安装 Node 依赖并构建 Java，默认浏览器地址 `http://127.0.0.1:8787/`。服务就绪后自动打开网页，后续启动会复用未改变的构建；Java 源码或 POM 更新后自动重建。重复双击会打开当前服务，同一目录的启动脚本不会同时运行多个实例（包括不同端口）。其他程序占用端口时会显示错误，不会停止占用程序。请保持启动窗口打开，关闭窗口或 Ctrl+C 停止 Java 服务。

公共富文本组件的构建产物已包含在目录中，运行时不需要联网加载编辑器。可使用 `-Rebuild` 强制重建、`-SkipBuild` 跳过源码更新检查（JAR 缺失仍会构建）、`-NoBrowser` 不打开网页。已具备运行依赖和最新 JAR 时不需要 Maven；首次安装或重建仍需要对应工具。不同副本的数据目录互相独立；直接调用 Java 命令时请自行保证同一目录只启动一个服务。

启动脚本会将简答 1.0.0／1.1.0 题库升级至 1.2.0，保留题库／题目 ID、富文本、图片和笔迹；旧题名合入题干开头，新界面只编辑和显示题干。进行中的答案与评分带入新版，旧历史保留；已完成轮次的答案作为新一轮草稿恢复。升级前请停止原服务，同一目录只运行一个服务。新版本已有状态或旧数据不兼容时不会覆盖。核心源码分工与升级细节见 [核心源码说明](docs/CORE_SOURCE.md)。

推荐在电脑本机网页左下角点击齿轮“设置”，开启“局域网连接”，设置至少 8 个字符的连接密码并保存。设置中会显示平板访问地址，默认局域网端口是 `8788`；本机入口继续使用 `8787`。开关、端口和密码校验摘要保存到 `.state/network-settings.json`，重启后恢复。密码留空表示保留原密码；修改密码或关闭连接会使现有局域网登录失效。平板连接同一网络，打开设置中显示的地址并输入密码即可。

设置只能从运行服务的电脑本机地址管理。服务不会自动修改 Windows 防火墙；连接失败时检查 Java 的专用网络访问权限或设置中选定的 TCP 端口。电脑需保持运行，各设备共用当前作答、草稿和历史。

原命令行临时口令方式仍保留：

```powershell
.\Start-QuizForge-Web.cmd -Lan
```

终端显示电脑的局域网地址和临时访问口令，平板在同一网络打开地址并输入口令。电脑需保持运行；系统防火墙如询问 Java 网络访问，仅为需要的专用网络授权。本程序不修改防火墙。`-Port 8788` 可更换端口；`-NoBrowser` 可只启动服务。

## 当前功能

- 左侧切换题库／拓展列表，点击后打开标签页，支持多标签和关闭。
- 标签栏与文件名栏采用紧凑布局，文件名上下不显示辅助文案。两侧栏都可隐藏／重新显示；桌面隐藏偏好保存在本浏览器，窄屏采用抽屉。
- 手机宽度不超过 600px 时，作答／历史／编辑／分值卡铺满内容区，按实际宽度排版，长题纵向滚动；切题箭头固定在底部。草稿仍使用原画布坐标，手机普通作答页隐藏笔迹叠层，进入草稿后可继续查看和书写。
- 题库列表来自 `question-banks/`；拓展列表来自 `extensions/`。刷新目录重新扫描，不提供导入界面。
- 切换到拓展并打开对应项，中间运行拓展自带样例；样例答案、草稿与正式题库分开保存。
- 右侧题目大纲采用只显示题号的矩阵，按原题序连续出现的题型分组；同类型隔着其他类型时不会合并或重排。保留已作答／提交结果颜色、上一题、下一题和点击题号切题。
- 单选拓展：选择自动保存、提交评分与解析、再答一次；评分由 Java 后端调用拓展规则完成。
- 简答拓展：题干、回答、参考答案和评分说明支持富文本与图片。回答自动保存，提交后等待人工评分；滑条步长为 0.5 分，点击“确认评分”保存结果，完成本轮前可以调整。
- 最后一题后有宿主绘制的分值卡，显示本轮已评分得分／整库总分、提交进度和待评分题数；也可从大纲进入。已提交题全部评分后，点击“完成练习”保存并结束本轮；仍允许有未提交题目，未提交题计 0 分，待评分题的分数保持为空。
- 上一题／下一题为内容区左右两侧固定箭头图标，移除底部切题栏。作答模式按当前可用区域居中显示题卡；长题保留纵向滚动。草稿的平移与缩放独立保留，切换模式不会改写笔迹或草稿视角。
- 草稿白板：底部悬浮图标条，选择、画笔、压力线宽、整笔橡皮、移动、撤销／重做、笔色和缩放；设置浮层提供粗细、纸张、仅笔书写和清空确认。鼠标箭头的选择工具（V）允许在草稿模式中操作题卡、选择答案和提交；切换工具保留笔迹与画布位置。
- 默认纸面为纯白空白。草稿纸色、方格与点阵仅绘制在题卡下方的背景层，笔迹绘制在题卡上方；已保存的纸面设置仍会恢复，普通作答页使用白色背景。
- 草稿工具条中的四角图标进入／退出全屏，同时请求隐藏浏览器地址栏，并隐藏网页左右侧栏、顶部标签栏与题名栏，让题卡、白板及工具占满可用区域；全屏按钮仅在草稿模式显示。切题箭头保持左右悬浮，退出图标保留在工具条中，退出后恢复原布局和侧栏显示偏好。返回作答、进入历史／编辑／分值卡或切换到非草稿标签时，自动退出由应用开启的全屏。浏览器不支持全屏时隐藏入口，拒绝请求时显示提示；Android Chrome 的实际系统栏行为由浏览器和设备决定。
- 白板按题目保存；退出草稿仍显示已有笔迹，切题和关闭标签等待保存。题卡与笔迹采用共同相机和固定逻辑宽度，缩放平移不会改写笔迹坐标。
- 手写笔书写、手指移动、双指缩放；关闭“仅笔书写”可用手指写。真实平板的手写延迟、掌触事件与软键盘体验仍需设备验收。
- 窄屏将列表与大纲变为抽屉；浏览器刷新和服务重启后可恢复答案与笔迹。
- 历史记录：题名栏时钟图标打开题库作答记录，一轮题库作答对应一条记录。完成后的记录保存整库分值汇总，打开后按历史中的题序用大纲和左右箭头查看各题及只读分值卡，题目、答案、评分、解析、草稿及页面均来自当时保存的数据。
- 历史列表每条记录右侧提供删除图标，确认后删除整轮记录；当前作答、白板与其他历史保留。进行中的历史被删除后，下次提交开始新轮。旧版汇总记录也按整条删除，不会合并其他旧记录。
- 编辑题库：题名栏铅笔图标进入拓展编辑器。单选编辑器支持题名、题干、选项增删、正确答案、解析和分值；简答编辑器支持富文本题干、参考答案、评分说明和满分。编辑模式可用左右箭头和大纲切题，未完成内容自动保存为服务端编辑草稿；草稿确认保存后释放旧页面，返回时恢复内容。保存全部修改先校验所有已修改题，再逐题保存；校验失败定位到该题并保留输入。取消或关闭编辑标签前确认放弃整轮未保存编辑。

本版包含单选、富文本简答与 AI 辅助评分，支持同一本题库混用多个拓展；没有工作区或题库／拓展导入界面，编辑模式目前修改已有题目。

## 手动添加目录内容

```text
quizforge_web/
  question-banks/         单选、目录式简答与 AI 简答示例题库
    short-answer-demo/   bank.json 与 assets/
  extensions/
    single-choice/       单选拓展（另有 3 道样例）
    short-answer/        富文本简答拓展（另有 3 道样例）
    short-answer-1.1.0/  AI 辅助评分简答拓展，保留旧版兼容历史
    short-answer-1.2.0/  两级富文本编辑与统一题干，当前简答版本
  shared/richtext/        带版本的公共富文本组件与编辑器分包
  .state/                当前作答、白板、历史、请求回执、编辑草稿、资源及恢复资料，请勿手动覆盖
  web/                   浏览器宿主与白板
  server/                通用 JS 规则执行器
  src/                   Java 后端和接口测试
```

题库格式为新协议，不是 V2 `.qbank` ZIP 文件。支持根目录 JSON 文件，以及包含 `bank.json` 和 `assets/` 的题库目录。每本题库声明稳定的 `id`、`title` 和 `questions`。旧文件的根级 `extension: {id,version}` 继续作为所有题目的默认拓展；新题库可省略根级 `extension`，在每道题中声明 `{id,title,extension:{id,version},data}`，也可用题目级声明覆盖默认拓展。所有引用必须指向已安装的精确版本。题目 `data`、答案、Schema、公开投影和评分由各自拓展拥有；Java 与宿主不包含具体题型分支。可复制示例 JSON 或整个题库目录修改题目，保持引用的拓展 ID／版本匹配。添加或修改后点击左侧“刷新目录”，当前标签读取更新内容，其他已打开标签在下次激活时更新。相同 ID 的数据文件不会被静默覆盖，冲突条目会显示错误。

新增 [混合题型练习](question-banks/mixed-demo/bank.json) 按“单选、简答、单选”排列，总分 7 分。大纲按连续出现的拓展 ID 和版本分组，不会将隔开的同类型题目合并或重排。练习、编辑、人工／AI 评分和历史按当前题目的拓展路由；分值卡仍由宿主统一绘制。旧格式保留原状态文件标识，题目级拓展格式使用独立的混合状态标识；已练习题库若手动改变绑定结构，应复制为新题库并使用新 ID，避免混淆原有当前作答。原文件及旧历史不会被自动改写。

混合题库的校验、分值汇总与历史投影按拓展 ID、版本和内容签名分组执行，顺序运行至多 512 项／约 512 KiB 输入的批次，输出恢复原题序；单项超限仍由既有规则进程限制拒绝。同一轮历史按拓展版本保存一次页面资源，各题只引用对应页面，旧单拓展历史继续读取原快照。浏览器仍只运行当前题目的一个 iframe，公共富文本按需加载，现有缓存容量和闲置释放规则不变。

已经练习过的题目会绑定内容签名。直接在目录文件中修改其题干、选项、答案等数据时，应给新题库使用新的 ID；修改拓展规则、Schema 或练习页面时，应发布新的版本号。否则后端会拒绝沿用旧状态并保留原文件。直接只改标题或题目顺序仍可继续原练习。应用内“编辑本题”通过受控接口同步更新题库和状态签名，可以保留题库 ID，行为见下文。

拓展目录必须有 `manifest.json`，声明 ID、版本、名称、页面 HTML/JS/CSS、规则、题目／答案 Schema 和样例文件；可用 `dependencies` 声明公共组件版本。页面调用 `QF.page.register / QF.save / QF.requestAction`，富文本通过 `QF.content` 使用；规则使用 `QF.defineType`。使用现有协议的新增题型只添加拓展与题库数据，不改 Java 或宿主 UI。详见 [实现契约](IMPLEMENTATION_CONTRACT.md) 与 [后端说明](server/README.md)。

拓展可提供 `getScore(data,state) -> {score,maxScore}`，负责自己的判分与分值输出；待评分结果的 `score` 为 `null`，已评分结果为合法数值。人工评分由拓展的 `review(data,answer,review)` 校验并产生结果，Java 通过通用接口汇总，分值卡由宿主设计。`GET .../summary` 读取本轮分值，`POST .../finish` 确认完成，有待评分提交时拒绝完成。现有单选 1.0.0 由规则执行器从已提交结果／未提交公开投影适配分值，不修改原判分协议。

正式题库与拓展样例状态分别保存在 `.state/`。当前状态与提交历史一起原子保存。未提交的练习页面仅接收拓展公开投影，不接收标准答案；编辑页面显式读取原始题目供作者修改。白板只保存世界坐标、草稿相机和纸张，不保存 DOM 或撤销栈。保存失败时暂停切题与关闭标签；可以重试保存，或确认放弃本地未保存内容后读取服务器状态。同一服务的浏览器共享当前练习数据，通过 revision 检查检测并发冲突，本版没有多用户账户。

编辑题目内容后，仅重置该题的答案、结果和草稿，其他题目与旧历史保留；只修改题名会保留当前作答。题库文件与练习状态通过可恢复事务一起更新，中断后完成原事务，发现无关手动修改时保留恢复资料并停止覆盖。手动修改目录文件仍遵循上述内容签名规则；应用内编辑由保存接口同步更新签名。

本轮第一次提交保存完整题库题序和公开题目；后续提交与评分更新同一条记录，全部提交并评分也要点击“完成练习”才结束。完成操作保存全库分值 `summary` 并冻结历史；有待评分的提交时不能完成，尚未提交任何题目仍可直接完成并保存一轮。完成后再次提交开始新轮，其他题的上一轮得分不会计入新轮。进行中的本轮可以查看；修改题目内容时结束当前轮，保留原题快照，后续提交另开一轮。只修改题名不结束当前轮。

删除全部历史会保留当前作答；此时分值卡采用仍有效的当前结果，再次完成会保存一条新记录。

旧版单题快照在读取时按连续不同题汇总展示，重复题号开始下一组；原数据保留。旧版没有保存完整题库题序，汇总只包含实际留存题，按旧提交顺序展示并标记“旧版记录”。更早未启用历史功能的提交无法重建。历史不会被自动删掉；每个集合的状态与历史共用 32 MiB 文件上限，达到上限时拒绝新写入并保留原数据。

编辑模式将有效或暂时无效的工作内容保存到服务端编辑草稿，不为后台题目保留隐藏 iframe。恢复草稿前检查稳定的 `draftVersion`；题目已经变更时保留旧草稿并提示冲突，不覆盖新题目。保存多个题目使用逐题事务；若中途存储或版本冲突，已成功保存的题保留，剩余修改及草稿保留并明确提示，可继续处理，整个题库的多题编辑不构成单一原子事务。

拓展可新增可选的 `editor.json`，声明编辑页面的 `entry/script/style` 文件。页面用 `QF.editor.register({onLoad,getDocument,hasChanges,exportDraft,importDraft,onFlush,onDispose})`；`getDocument` 返回正式 `{title,data}`，草稿导出与恢复保留未完成表单，宿主提供保存按钮、校验和冲突处理。页面切换前调用 `onFlush`，释放时调用 `onDispose` 清理编辑器、监听器等资源；不支持草稿恢复的旧编辑器须先保存修改才能切换。编辑资源独立于已冻结的练习页面签名，新增编辑器不会使原练习失效。

规则在带截止时间、输出预算和文件访问限制的子进程执行。本版适用于管理员手动放入的可信本地拓展，不作为任意恶意第三方代码的完整操作系统沙箱。

## 切题缓存

浏览器缓存最多 12 个题目响应，合计最多 16 MiB（JSON 的 UTF8 大小）；拓展页面资源最多 4 份、合计 4 MiB；公共 SDK 静态／编辑器分包分别作为缓存项，合计最多 4 项、8 MiB。按最近使用顺序淘汰，闲置 5 分钟自动释放；关闭标签释放对应题库的缓存，无其他标签引用的拓展页面资源也会释放。刷新目录清空题目与拓展页面缓存并更新当前集合，其他标签下次激活时重新读取元数据；固定版本 SDK 继续受独立上限控制。刷新网页自然释放所有内存缓存。未缓存隐藏 iframe DOM。

重访缓存题目或已有标签时先请求轻量 `/stamp`，核对当前 revision、题目内容与拓展资源版本。没有变化则使用缓存；有变化则重新读取公开题目和当前状态。服务器重启也会使版本失效。暖缓存版本检查不执行 Node 题目投影，所以重复切题无需再次执行完整评分规则或读取同一份页面资源。保存后的确认响应更新缓存；检查失败会保留当前题目并提示失败，不把过期数据当成已经确认的新状态。

最多打开 8 个标签，同时只保留当前标签的题型 iframe、白板及编辑器运行实例；切标签确认保存后释放后台实例与撤销栈，返回时从已保存内容恢复。后台标签只保留元数据，题目响应和资源由上述缓存限制控制。Java 的练习状态内存缓存也按最近使用顺序限制为 8 个集合、合计 64 MiB（按编码后的 JSON 大小计）；淘汰后从磁盘重新读取，已保存状态和请求回执保留。

保存请求同时携带当时显示的题目版本，避免手动改题后将旧画面中的答案提交给新题目。遇到内容版本冲突会保留当前输入，并提示读取服务器状态后重新作答。

## 富文本简答题与目录式题库

现有 `question-banks/*.json` 继续兼容，同时支持 `question-banks/<题库目录>/bank.json`。新增“简答与富文本练习”包含 3 道题，展示格式、图片、自动保存和人工评分。

目录式题库采用以下结构：

```text
question-banks/一本题库/
  bank.json              元数据、题序、题型、结构化内容与资源 ID
  assets/
    <内容哈希>.webp       图片等二进制资源
```

富文本采用结构化 JSON（`formatVersion:1`），支持段落、标题、粗体、斜体、下划线、列表、引用、代码和图片；图片节点仅保存 `attrs.assetId`。单张 PNG/JPEG/WebP/GIF 最大 4 MiB，当前页已加载图片合计最大 16 MiB。题库和拓展样例资源导入 `.state/resources/` 持久区；作答图片也进入该区。编辑目录题库时将题目引用的资源补入题库 `assets/`，便于搬运。资源按内容哈希保存且不可覆盖；本版不自动删除资源，移动题库或删除历史不会误删其他历史依赖。

公共组件按版本保存在 `shared/richtext/`，当前简答引用 `dependencies:[{id:"quizforge.richtext",version:"1.1.0"}]`，旧 1.0.0 保持原样。只读渲染和完整 Tiptap 编辑器分包，编辑时才加载重包；各拓展不复制组件。组件首次使用后固定到 `.state/sdk/`，旧历史保留版本依赖，同版本源码变化会报错，升级应发布新版本。新版重建使用 `npm run build:richtext-advanced` 和 `npm run build:short-answer-advanced`，源码位于组件版本目录的 `src/`。

内联富文本保留基础工具，右上角“展开高级编辑”打开完整工具窗口。字体、字号、颜色、高亮、上下标、段落对齐／行距、链接、公式、表格行列／合并拆分和图片宽度等工具集中显示；“返回基础编辑”回到题卡。展开与返回保留同一编辑器和撤销记录。高级正文宽度取自内联正文，题干编辑与练习共用相同卡片宽度和排版。公式以 LaTeX 保存、MathML 渲染；表格、公式和图片仍是结构化文档，AI 转换保留其内容语义。高级模式不会额外开启题型 iframe。

简答题提交后为“待评分”，参考答案和评分说明在提交后显示。滑条以 0.5 分为步长，点击“确认评分”才保存；结束本轮前可以调整。分值汇总区分已评分得分和待评分题数，已提交题全部评分后才能完成；未提交题仍允许完成。完成后的整轮记录只读冻结。

题库编辑草稿单独保存到 `.state/editor-drafts/`，允许空题干等未完成内容；切题和切标签确认保存后销毁旧编辑页面，返回时恢复。当前页保持一个活动题型 iframe、一个完整富文本编辑器；后台释放 iframe 和白板，只保留数据，最多打开 8 个标签。撤销栈仅在当前页面保留，切换恢复正文，不恢复撤销栈。保存草稿失败会暂停切换。

当前支持同库混合题型；音视频以及 ZIP 导入导出尚未加入。

## AI 辅助评分

左下角齿轮 → **AI 评分**，填写 OpenAI 兼容接口的基础地址、模型名称与 API Key，开启并保存。基础地址不包含 `/chat/completions`，系统自动追加。按模型实际能力选择 JSON 模式、JSON Schema 或普通文本兼容模式；含图片的题干／回答须选择支持视觉的模型并勾选图片能力。云端地址使用 HTTPS，本机与私有局域网模型允许 HTTP。连接测试显式发送一次模型请求，服务可能计费，测试使用已保存的配置。

打开新增的 AI 简答示例题库，提交富文本回答后点击 AI 评分。模型建议不会立即改动正式分数；查看理由、按 0.5 分调整滑条，再确认保存。人工评分仍可直接使用。确认后反馈同时显示实际最终得分、AI 原建议与理由，后续人工改分保留这些理由；整轮历史冻结最终结果与评分来源，查看历史不调用模型。已使用的简答 1.0.0 不覆盖，新能力发布为 1.1.0。

拓展仅实现可选 `prepareAiGrading(data,answer)`，返回题目、答案、参考答案、评分说明的文字／图片内容块，以及满分与精度。Java 从已提交的题目与答案构造输入，图片只从本地资源 ID 读取；页面不能替换提示词、服务地址、模型或密钥。共享 `AiGateway` 负责单次模型消息调用，`AiGradingService` 负责异步任务、校验、重试与确认；以后可增加供应商适配器。当前先提供 OpenAI 兼容适配器，服务的具体模型能力仍需按供应商配置。[百炼兼容说明](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)与 [Ollama 兼容说明](https://docs.ollama.com/api/openai-compatibility)可供配置时参考。

网络临时错误采用有限退避；认证、额度、配置错误直接显示原因。无效 JSON、越界分数或精度错误最多进行一次模型修复，每个任务所有重试与修复合计最多 3 次实际模型调用。失败后可手动重试，重新评分保留当前正式成绩，直到用户确认新建议。任务绑定提交、题目、拓展版本和活动轮，重答、改题、人工改分或完成本轮后，旧建议不能覆盖新状态；白板书写不使建议失效。

密钥仅由后端保存在限制文件权限的 `.state/ai/profile.json`，读取设置只返回是否已配置；浏览器表单在关闭时清空输入，局域网设备不能修改配置。不要分享该配置文件。任务记录保存在 `.state/ai-grading/`，与正式成绩分开保存，后台评分不会为题型保留隐藏 iframe。任务内存缓存最多 32 条，串行执行并最多排队 16 条；新记录准入限制为 4096 个文件或 256 MiB，不自动清除旧记录。模型调用使用输入／响应预算，单次最多 8 张图片、合计 8 MiB，图片本身仍受 4 MiB 资源上限限制。服务中断的任务不会自动再次请求模型，可显式重试；已生成的候选在重启后仍能读取和确认。

本次实现使用本地模拟服务验证协议、重试和保存流程，不发送用户数据到真实模型。实际评分效果在配置模型后确认。
