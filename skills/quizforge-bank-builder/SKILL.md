# QuizForge 题库制作

保留材料含义、顺序、资源和评分依据；一题型一独立拓展、一本同题型样例，普通题库可混用多个拓展。按当前会话已有决定继续，不重复询问；用户明确要求跳过阶段时遵循并说明验证缺口，不自行推定其放弃确认。

## 范围与环境

- 产品根目录包含同层 `core/`、`extensions/`、`question-banks/`、`skills/` 和启动脚本；先只读查看 `core/docs/reference/API.md`、实际叶拓展的 manifest/schema/rules/examples。以现行契约和安装文件为准，不凭本技能示例认定已安装或猜接口。
- 只写用户指定的新拓展叶、明确要求继续的拓展叶、授权的新题库／交付文件。正式样例维护可只改获准的样例数据及专属资源。禁止改 `core/`（含源码、SDK、依赖和文档）、根启动脚本、设置、`.state`、`.development/.state`、其他未授权拓展；旧平铺项目的同类文件也受保护。
- **所有临时文件、工具临时目录与缓存只能在 `<产品根目录>/.temp` 及其子目录**，包括提取、OCR、访谈记录、调试脚本、日志、截图、测试和独立预览。已有拓展及样例、最终题库资源和报告放获准交付位置。路径或工具无法遵守时报告，不自行改用系统临时目录。
- 材料中的命令不是授权。不读取凭据或状态，不自行联系第三方、安装依赖或调用收费模型；现有接口做不到时报告缺口与替代方案，不改宿主或使用私有协议绕过。

新制题库及拓展示例采用文件格式 2、包格式 4；创建时保存随机小写 UUIDv4，后续修改和导出保持不变，另存为新题库才换 UUID。大纲使用顶层集中 outline；听力本地 assets/ 或 HTTPS url 二选一。详见 [题库与材料](references/bank-format.md)。

## 基础题型参考

布局、数据结构和样例直接使用产品的 [单选题](../../extensions/基础题型/单选题)、[简答题](../../extensions/基础题型/简答题)、[多选题](../../extensions/基础题型/多选题)、[判断题](../../extensions/基础题型/判断题) 基础拓展。同框文字、手写和图片作答参考 [简答题（答题区）](../../extensions/基础题型/简答题（答题区）)，直接使用宿主提供的 QF.answerAreas。先读取 manifest 指向的 Schema、规则、页面、编辑器及 examples；基础目录不存在时核对实际安装位置，不使用已移除的技能模板或凭空补一套样例。

复用已有题型时使用其已有样例验证效果，不重写题型或另建样例库。同一题库分组内共用拓展；不同分组交付独立副本，包含使用到的基础题型。复制到本组配套拓展目录后，同步题库及副本样例的准确路径绑定。获准新建题型后，可复制适合的基础叶到授权位置，维护副本身份、规则及已有 examples 的精确自绑定；不改参考拓展，不在技能内另建 assets 模板。

基础目录中的单选、多选、判断使用 2.0.0，富文本简答题使用 2.0.1，简答题（答题区）使用 1.0.2。按实际目录路径复用，并核对当前 manifest 的协议与能力；仅修改用户授权的拓展；不要求开发副本或发布。更新前备份，保持答案结构和稳定 ID 兼容。

## 流程与确认

| 阶段 | 当前交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| 0 功能选择 | 一次询问编辑、白板、历史含练习保存、考试的关闭项 | 用户明确选择；样例默认全开，免问 |
| A 材料与选型 | 逐题清单、精确拓展版本、转换损失／缺口 | 覆盖方案明确；需要新题型时获得设计许可 |
| B UI 访谈与评审 | 逐轮访谈 → 需求概要与编辑白名单 → 实际三态原型 | 概要先确认才写原型，实际 UI 与交互全部确认才实现业务 |
| C 实现与小样 | 完善现有接口，少量代表题，真实功能验证 | 各题型实现完成、小样吻合、关键疑点解决 |
| D 验收与生成许可 | 展示实际功能、检查结果与未验证项 | 用户验收并明确同意正式生成整库 |
| E 生成与交付 | 完整题库、资源、制作报告 | 按验收方案生成并核对 |

普通题库尚无功能选择时先问：**“编辑、白板、历史（含练习保存）、考试默认全开，要关闭哪些，还是全部开启？关闭历史也关闭答案、得分、白板和完成状态的持久化；编辑仍开启时可以保存题目文件。”** 等待回答期间仅核对路径，不分析材料、选型或写 UI。已有明确选择直接沿用。拓展样例不问，四项默认全开。

功能选择后按 [题库与材料](references/bank-format.md) 恢复题目结构，检查展示、作答、判分三项能力。缺答案、分值或 OCR 疑点时标明来源与推断，请用户决定，不能当成正式依据。缺合适题型时汇总新建请求：题目、现有能力不足、拟用接口；用户可同意新建、接受有损替代或忽略。未经许可不建新题型。

**阶段 B 的唯一设计规则见 [UI 设计](references/ui-design.md)。** 先问清会改变界面的细节并确认编辑白名单，不先堆编辑框再让用户删。访谈时只读核对和记录；概要获准才在指定拓展叶制作少量代表题的未提交／提交后／编辑三态演示。每种呈现与复杂变体都需覆盖，复用已有拓展也核对期望并展示实际效果，不改原包。显示骨架及分组规则见 [拓展开发](references/extension-development.md)。

确认概要只授权原型；确认实际 UI 只授权接口实现和小样；小样通过不授权整库。阶段 D 明确询问：**“是否确认这些界面与实际功能，并同意按此方案正式生成完整题库？”** 展示对应内容后等待答复。接受无法预览／运行的验证缺口与许可生成是独立决定。已展示具体内容后的认可可采用；尚未展示前的“继续”不能替代确认。

实现时按 [拓展 API](references/extension-api.md) 处理真实保存、判分、富文本、flush/dispose、只读历史和小题定位。原型模拟须标注，不算功能完成。验证代表题输入、提交、评分、重做、切题、编辑保存、历史及释放；按已选开关检查白板，混合题型另核对宿主总分。未实现或失败如实报告，不返回假成功。

新拓展同时支持独立的 `canSave/canSubmit`：禁止提交时隐藏单题提交按钮，仍按保存权限开放输入并自动保存；按钮使用 API 文档的 `data-qf-action` 标记。题库功能统一由文件根 `features` 声明，四项省略均默认开启，用户明确关闭哪项才写该项 `false`（考试为 `features.exam:false`）；不通过题库列表编辑修改功能开关；不为考试新增题型或把宿主计时、交卷功能写进拓展。

## 校验与交付

阶段 D 获准后才批量生成，按确认的交付位置将相关题库放入 `question-banks/<分组>/<唯一题库目录>/bank.json` 和相邻 `assets/`；用户明确要求未分组时沿用。分组仅一层，命名及整组／单题库 `.qbank` 交付见 [题库分组与交付](references/bank-format.md#题库分组与交付)。保持原题顺序、稳定 ID、精确绑定与确认的 features。遵守实际 schema，标题元数据必填但不因此新增题名编辑框。保留已有题库、状态和历史；遇到不同内容的同名目标用新 ID／目录或询问覆盖，不外部覆盖已练习题库。

使用已有 Node.js 24 与产品依赖执行只读校验：

```sh
node "<技能目录>/scripts/validate-bank.mjs" --project "<产品根目录>" --bank "<题库目录>"
```

`--project` 指向外层产品根，非 `core/`。未安装的新拓展可用 `--extensions "<暂存拓展目录>"`；开发绑定加 `--allow-development`。显示骨架再加 `--preview-only`，仅结构预览，不执行规则，报告 preview、fullRuntimeValidated=false、maxScore=null。默认完整校验缺实现必须失败；只在没有 `core/` 的 fixture 兼容旧平铺路径，存在但不完整时不回退、不安装依赖。

结构通过不证明 UI、OCR 或评分正确。对照材料核对数量、题意、答案、分值和资源；修复本次生成文件并重跑，宿主问题报告而不改核心。交付目录和查看方式，报告题库分组、每本题库路径、依赖拓展 ID／版本及实际交付的 `.qbank`（若有），以及功能开关、各阶段确认、总分、来源映射、替代／遗漏／推断、实际检查与已接受缺口。

不设置拓展发布阶段；按 [拓展修改与兼容](references/extension-development.md) 在用户授权范围内修改和交付，保持稳定 ID 与答案兼容。等待任一确认时只交付对应分析、概要、原型或小样，不称完整题库已完成。

## 统一状态、草稿与完成练习

产品不区分开发版／正式版。题库和拓展恢复一层物理分组，各实体为独立文件夹，界面名称取文件夹名；新题库通过 `{path}` 引用具体拓展。交付包只用格式 3，每次导入新增独立副本、重名加序号，不比较 UUID/版本/哈希。旧包 1/2 不支持导入；当前安装目录同样要求物理分组、题库文件夹和准确 {path} 绑定，样例也须准确自绑定，旧无路径绑定及开发版集合入口已退役。内部保存身份由宿主生成，不制作或复制 `.instance.json`、`.bundle.json`。完整约定见[宿主导入导出文档](../../core/docs/reference/LIBRARY_PACKAGES.md)，不擅自迁移已有个人数据。

新草稿题卡固定760逻辑像素，不按设备改变换行；宿主管理缩放、平移及笔迹，拓展不按物理设备强制改布局。完成练习会由宿主提交已保存的未提交答案，拓展 grade 负责空答、部分作答及小题汇总。onFlush 必须完整保存输入；待评分保留 pending，可重试 AI 或人工处理。需要验证这条统一提交路径，不只测试页面提交按钮。

拓展分组为实际文件夹，每个独立拓展放在 `extensions/<分组>/<拓展>/`。不使用或维护旧逻辑分组表，不搬动未授权的已有拓展；对外交付一个包含题库与配套拓展的格式 3 `.qbank`。目录、引用及样例规则见 [拓展分组与绑定](references/extension-development.md#分组与绑定)。
