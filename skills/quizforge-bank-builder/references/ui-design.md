# UI 访谈、设计与评审

阶段 B 使用：功能选择与材料选型已完成，新题型已有设计许可。先访谈并确认概要，后制作原型、确认实际三态；既有明确决定直接沿用，不重复问。

## 设计前逐轮访谈

借鉴 [grill-me 的分支访谈](https://github.com/mattpocock/skills/blob/main/skills/productivity/grilling/SKILL.md) 与 [Superpowers 的需求澄清](https://github.com/obra/superpowers/blob/main/skills/brainstorming/SKILL.md)，本流程自包含，不安装或调用其他技能。

- 先查看材料代表题、现有 UI 和接口。事实自己查，只向用户询问效果与取舍，不问接口名或 Schema 字段。
- 沿依赖顺序问：题目结构／题干 → 作答 → 提交后 → 编辑项目与控件 → 设备版式。默认每轮一个关键问题，给 2–3 个具体选项、推荐及简短取舍；互不依赖的决定可一起问，不发长问卷。
- 收到“简洁”“富文本”“都能改”时，用本题实例追问范围，不能据此添加题名、要求、编号等输入框。发现矛盾先说明影响再澄清。只追问会改变 UI 的未决细节，不为凑数量重问已决定内容。
- 有适用的提问工具就使用，没有则文字提问并结束本轮。预选、沉默和超时不是回答；等待中仅只读核对和记录，不复制模板或编写 UI。用户明确采用推荐或让 Agent 决定时列出具体方案，不声称此前已经确认。
- 记录到指定 `.temp/<任务>/ui-decisions.md`：按题型保存三态决定、编辑白名单、排除项、疑点与确认依据。无文件工具时在会话维护概要并说明限制。用户改意向时更新对应决定。

| 分支 | 要问清的效果 |
| --- | --- |
| 题干与结构 | 独立题还是共享材料小问，材料／要求如何合并，哪些内容必须分开 |
| 作答 | 实际控件，文本／富文本／图片／公式，选项排列、边框、行高与展开方式 |
| 提交后 | 标准答案、对错颜色、解析、人工分数条／AI 反馈是否需要，评分进度与失败提示 |
| 编辑 | 哪些内容允许改，每项为何需要、合并还是分开、直接点选还是文本／富文本控件 |
| 多小题 | 仅适用组合题：大纲显示父题或小题，共享材料／小问如何编辑和展示结果 |
| 版式 | 对齐、正文宽度、间距、手机／平板使用；多富文本目标怎样切换 |

跨题型相同偏好可共用，差异单独问。编辑／白板／历史沿用阶段 0；AI 自动启动由应用设置决定，不为每题新增开关。复用正式包时围绕实际能力访谈，超出能力回到选型或申请新开发版，不承诺原包没有的行为。

访谈结束展示简短三态概要、编辑白名单与明确排除项，问：**“这些布局和编辑项目是否准确？确认后我按清单制作实际 UI 原型，再让你看效果。”** 等待明确答复；既有会话已明确确认相同概要时不再问。概要确认不代表原型、业务或整库已经获准。

## 简洁布局与编辑白名单

默认只有三个内容区：**题干**（合并材料与要求）、**作答区**（实际题型控件）、**答案与解析**（提交后显示，评分依据按需放入）。不重复元数据题名，不另加要求／评分标准面板或标签页。布局不是统一私有 Schema，不能为了套模板改正式包或丢必要内容。

编辑沿相同内容顺序，只实现确认的 **项目 → 用途 → 控件形式** 白名单。通常讨论题干、必要作答配置、答案与解析，满分是否开放由访谈决定。参考答案与解析可同一区域，底层仍按实际 schema 保存；不因一个区包含多个字段就把字段逐项做成输入框。

默认不开放题号／小题编号、内部 ID、元数据题名、绑定／版本、大纲、来源／难度配置。数据必须存在或需要显示不等于需要编辑；保留原 title、稳定 ID 和未修改字段，新题元数据可从题干生成。文本回答是练习输入，不额外做“用户答案”配置框。额外编辑项说明具体操作用途并确认，白名单外连隐藏的高级页／折叠面板也不做；原型中多出的控件删除或提出变更，不以已实现要求用户接受。

两个 [模板](../assets/) 仅供布局起点：

- [通用文本题](../assets/development-scaffold/)：题干、文本作答、提交后答案与解析。其他题型自行选择作答控件。
- [单选题](../assets/single-choice-scaffold/)：左对齐、选项保留圆角框，无额外“请选择”提示；提交后正确项绿、错选项红，不重复“你的选择”，重做清除颜色。编辑选项默认一行自动增高，直接点选正确项、整行绿，不再加答案下拉框；满分开放时用下划线编辑，无数字箭头／分数菜单。

模板行为和可选评分条是本地演示，正式功能仍由接口保存。单选演示答案表须随代表题维护，实际提交／历史使用宿主投影的正确答案，不能把演示着色当作已判分。打分条和 AI 反馈可按需出现在提交后区域，客观题也可用，不默认每题必配。

## 实际原型与确认

概要获准后按 [开发流程](extension-development.md) 在同一开发叶制作显示骨架。每种呈现／作答方式选材料中的实例，长题干、图表、共享材料、小问等复杂变体另取代表题，展示同一道题的三态：

| 状态 | 必须展示 |
| --- | --- |
| 未提交 | 题干、作答、恢复与提交条件；隐藏标准答案和私有评分依据 |
| 提交后 | 服务器结果的呈现、答案与解析、得分／反馈、需要时的评分进度／失败与重做 |
| 编辑 | 白名单内的实际控件、切题保留与保存失败处理，正文宽度与练习一致 |

附简短交互表：**用户动作 → 页面反馈 → 保存／判分归属 → 失败处理**，覆盖输入、提交、评分、重做、编辑保存和题型专用动作。题库总分、历史列表、标签和宿主导航不由拓展重做。

用正常提交按钮演示结果、宿主编辑入口演示编辑，不增加三态切换栏。少量本地 JS 可模拟，明确标注“界面演示”，不调用真实保存／评分／AI／上传。必要骨架与真实业务的边界见开发文档；未完成真实动作不能假成功。

提供实际宿主样例或可打开 HTML／截图，并说明如何查看。既有正式包不改代码；独立临时原型只放指定 `.temp/<任务>/preview/`。手机可读可操作，三态正文宽度一致；富文本性能和活动编辑器约束按 [API](extension-api.md#公共富文本-qfcontent)。仅 JSON、schema 或文字承诺不算可视预览；没有图形工具则提供三态线框及交互表，说明缺口，由用户决定是否接受替代。

展示后询问 **“请确认这些三态 UI 和交互，或指出调整。”** 并等待。所有涉及题型实际 UI 获准后才进入 C，较大变化再确认变化部分。记录概要与原型各自的确认；功能验收、生成与发布条件统一按 SKILL.md，不因原型通过或结构校验通过自动推进。
