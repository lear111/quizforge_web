# 开发版拓展

开发版是不完善的正式版，与正式版使用同一 QF 页面、规则、编辑和保存管线。区别只有开发标签、文件热刷新及测试数据隔离，不再公开区分 UI/runtime 阶段，也不为新拓展提供专用 QF_PREVIEW 协议。未调用某个接口不会阻止页面显示；调用尚未实现的动作应明确报错，不能伪造已保存或判分成功。

普通启动，在本机左下角设置开启开发者模式。正式版与开发版在同一拓展列表显示；一个叶目录一个题型、一本同题型样例，相关叶可用物理文件夹分组。开发叶名全局唯一，移组不改叶名时开发绑定不变，见 [目录分组](EXTENSION_GROUPS.md)。

## 从显示骨架到完整功能

新开发叶以 `development.json` 标记，例如 `{}` 或 `{"name":"阅读题 · 开发版","description":"设计中"}`。新制作优先使用普通 `manifest.json` 声明正式 ID、计划版本及 entry/script/style/examples；规则、Schema 和编辑器逐步补齐，缺少这些实现不应阻止已有页面显示。最小可用骨架见技能的 [development-scaffold](../../skills/quizforge-bank-builder/assets/development-scaffold/)。

先接 `QF.page.register({onLoad})` 及真实公开题目投影，让宿主切题、样例注入、宽度及生命周期与最终产品一致。已确定分值时 `getScore` 输出真实 maxScore；尚未实现 grade、review 或编辑保存时省略对应实现，或抛带 `code:"DEVELOPMENT_NOT_IMPLEMENTED"` 的错误。开发请求的缺实现会局部报错，不会把模拟分数、模拟保存当作正式结果。正式版校验不会因此放宽。

用户许可新题型设计后，在指定开发叶直接制作少量代表题，展示未提交、提交后与编辑状态，再等待对应 UI/交互确认。UI 阶段允许少量本地演示脚本，但必须标注“界面演示”，不调用真实保存、判分、AI 或上传来伪装功能完成。基础加载、注册和投影是显示骨架；真实作答保存、提交判分及编辑保存在确认后实现。未实现动作可禁用并提示原因。保存文件后，当前可见样例热刷新；输入与未保存修改不能被刷新悄悄丢弃。

`examples` 是普通题库格式，ID 为 `examples`，仅使用自身 manifest 的精确 `id/version`，可含多道同题型变体。新样例省略 features 或将 editing、whiteboard、history 全写 true，不问关闭项。普通测试题库显式用 `{"development":"实际叶名"}`，可与正式精确绑定混用；正式题库不会自动切到开发版。

旧用户目录只读兼容：旧 `mode:"ui"` / `mode:"runtime"` 不再选择公开执行管线；旧 marker 的 entry/script/style/examples/editor/assets 可以补足尚未完成的 manifest 声明，manifest 已有字段优先。没有 manifest 的旧 UI 页面仍能显示，宿主内部可适配旧样例读取；新 Agent 不创建旧 QF_PREVIEW 页面、不重写旧用户文件。旧无样例目录只能展示占位设计，不能称为已验收题型。

## 资源、样例和测试

练习和编辑页面固定图片/字体用 `manifest.assets`，所有路径限制在本叶内；旧标记 assets 仅兼容读取。支持 PNG/JPEG/WebP/GIF/SVG、WOFF/WOFF2/TTF/OTF，最多 100 项、单项 1 MiB、合计 8 MiB。动态富文本图片用 `QF.resources` 和内容哈希。新正式版本的资源声明应完整写在 manifest 中，不依赖删除后消失的开发标记。

功能实现后，样例与普通题库执行相同规则、features、编辑和保存。editing 开启时可以写回自身样例题目及专属图片，不能通过样例编辑改代码。history 开启的开发作答、白板、历史、编辑草稿、资源和 AI 任务由宿主隔离在 `.development/.state/`；关闭 history 后这些练习数据只属于当前浏览器页面会话，刷新或关闭浏览器标签后不能恢复。editing 仍开启时题目文件与编辑图片可持久保存。Agent 不直接读写状态目录。

开发代码修订使用独立测试身份；测试题库数据变动只重置变化题的当前作答，旧历史保留。开发绑定不承诺正式发布后的长期数据兼容。发布前分别验证未提交、提交、评分、编辑保存、只读历史、切题与资源释放；预览检查不能代替这些行为。

技能校验器默认做完整结构、Schema、规则、初始分值、资源和样例检查。开发绑定加 `--allow-development`；尚未完成时另加 `--preview-only`，只检查声明/结构/资源及已提供的 Schema，不执行题型规则、提交或评分。报告必须区分 preview 与 full，preview 的总分为 null、完整运行验收为 false，即使退出码为 0 也不能称功能完整。

## 正式版更新与人工发布

已发布版本的代码不原地修改。用户要求更新旧正式拓展时，先复制到新的唯一开发叶，加开发标记，再修改；旧正式目录、ID/版本内容及旧题库绑定保留。发布前为副本确定新的正式 version，样例使用这个副本最终精确 ID/版本。只维护旧正式样例题目及其专属资源是数据例外，不需要升代码版本；manifest.assets 中的静态资源仍属于代码。

当前不提供发布按钮，Agent 不调用发布 API。完成完整校验和实际小样后，由用户决定是否发布；用户明确确认后，人工移除该开发叶的 development.json，再按正式精确绑定重新校验。检查同 ID/版本不存在另一份不同代码，确认所有必要声明在 manifest/editor 中，而不是只存在于标记。正式旧包和其他题库不自动改绑；上传 Hub 另行处理。之后更新再次先复制并加开发标签。

制作范围由 [Agent 工作流](AGENT_BANK_WORKFLOW.md) 与 [技能](../../skills/quizforge-bank-builder/SKILL.md) 约束：只写授权开发叶、新题库和输出，不改 core、启动脚本、设置、其他拓展或状态。这是书面工作规范，不是新增文件写保护锁。
