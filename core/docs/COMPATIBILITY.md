# API v1 与更新兼容政策

本文规定应用更新、拓展发布和题库读取的兼容边界。完整页面、规则、评分、AI、资源与生命周期接口见 [实现契约](../IMPLEMENTATION_CONTRACT.md)；制作题库与新拓展见 [Agent 工作流](AGENT_BANK_WORKFLOW.md)。

## 当前实现的版本

应用自己的版本、拓展的 `id@version`、宿主 Extension API 版本、题库格式版本和公共 SDK 版本分别管理。当前应用支持 **Extension API 1.0／1.1／1.2** 与 **题库格式 1**，尚未实现 API v2、格式 v2、应用更新器、Hub 或任意题型之间的通用迁移。

新拓展可在 Manifest 中声明：

```json
"requiresApi": {
  "major": 1,
  "minMinor": 0,
  "capabilities": ["practice", "score", "editor", "lifecycle"]
}
```

整个 `requiresApi` 缺省表示需要 API 1.0。显式声明时 `major`、`minMinor` 必填，必须是整数，分别至少为 1、0；`capabilities` 可省略，省略等于空列表。对象仅允许上述三个字段；能力须为不重复的非空字符串。当前接受 `major:1,minMinor:0` 、`minMinor:1` 或 `minMinor:2`，未来版本和未实现能力明确拒绝，不能静默当作 v1 运行。

支持的能力清单：

| 能力 | 含义 |
| --- | --- |
| `practice` | 页面注册、恢复作答、保存与提交 |
| `editor` | 原题编辑与读取文档 |
| `editor-drafts` | 暂时无效编辑内容的导出与恢复 |
| `score` | 拓展判分/分值接口与宿主统计；API 1.2 的 getScore 可选 outlineStates 提供小题状态 |
| `manual-review` | 待评分结果与人工评分确认 |
| `ai-grading` | AI 任务、重试、候选与确认 |
| `resources` | 内容哈希图片上传、读取 |
| `richtext` | 使用独立的公共富文本接口和文档约定 |
| `navigation` | 练习中的切题请求 |
| `outline-items` | API 1.1 可选的有序小题导航，声明时需 `minMinor:1`；见 [接口说明](SUBQUESTION_OUTLINE.md) |
| `lifecycle` | flush 与 dispose 保存/释放钩子 |

能力清单说明宿主实现了哪些公共协议，不会自动让某个页面获得写入或评分权限。页面必须继续检查 context.capabilities，历史始终只读；新拓展通过 `requiresRichText` 声明富文本 API、文档格式、文档约定及能力，应用选择兼容实现。旧精确 `dependencies` 保留兼容读取。详见 [富文本服务](RICHTEXT_SERVICE.md)。

拓展页面和编辑页面响应携带 `apiVersion:{major:1,minor:2}`，对应 iframe 中公开 `QF.api:{major:1,minor:2,capabilities:[...]}`。规则环境也提供只读 `QF.api` 描述，但能力列表不意味着规则中能调用浏览器方法。API 1.2 只在 getScore 返回值中增加可选 outlineStates，采用 unanswered/correct/incorrect 三态，保留 score/maxScore 的含义，不新增方法或能力名称。历史按每个冻结页面自己的 `apiVersion` 选择接口；旧页面或旧规则请求没有该字段时按 1.0 处理。API v2 上线前必须实现新运行层及旧版路由，不能先接受 v2 声明。

新题库和拓展示例建议显式填写顶层 `formatVersion:1`。旧文件没有该字段时按格式 1 读取，不重写文件。显式字段只支持数字整数 1，其他值拒绝。这个顶层版本与简答 `data.formatVersion`、回答文档的格式版本相互独立，题型内部数据仍由各拓展拥有。

题库格式 v1 增加可选根 `features`，仅允许 `editing/whiteboard/history` 三个 boolean；省略对象或某项等于 true，不改写旧文件，也不需要提高题型 API 版本。不支持题目级覆盖。关闭 history 关闭全部练习持久化（含答案、成绩、白板、完成、历史及练习图片/AI 任务），不删除原有保存数据；临时数据仅供当前浏览器页面会话。editing 仍开启时题目与编辑图片可以保存。普通题库、正式样例及开发集合使用相同 QF 管线和 features 语义。开发完整度不是执行模式，未实现操作局部报错，不伪造保存或评分。见 [题库格式](QUESTION_BANK_FORMAT.md#整库功能开关)。

## 更新与发布规则

开发版与正式版共用同一 QF 管线；新开发标记为 development.json 的普通对象，不公开 ui/runtime 执行模式。更新旧正式代码先复制到新唯一开发叶并加标签，旧代码保留。当前不提供发布按钮，Agent 不调用发布 API；用户确认完整验证后人工移除标记，检查最终版本、样例精确自绑定及声明完整，再运行正式校验，不自动改旧题库。骨架预览校验不执行规则或评分，不能冒充完整验收。具体流程见 [开发版拓展](DEVELOPMENT_EXTENSIONS.md)，这些作者工作规范不新增程序文件写锁。

- **同一 API 主版本保持向后兼容。** 可以新增可选参数、接口和能力，保留既有参数含义、返回结构及约定行为。核心内部可重构；破坏性改动必须另行发布 API 主版本和兼容运行层。
- **题型包版本精确绑定。** 题库继续使用保存的 `id@version`，安装新版本或更新应用不切换绑定。已发布拓展版本代码和组件的相同版本不得原地改字节；受控样例题目编辑的例外见下一项。当前页面可以使用应用为同一富文本接口与文档约定验证的新实现；基础约定不会被扩大为高级约定。旧题库需要的安装包和历史依赖的固定组件/页面必须保留。
- **样例编辑只维护题目数据。** editing 开启的正式/开发样例可以由应用受控编辑写回 examples 及只由样例引用的相邻图片；不会允许改 manifest、规则、Schema、页面或 SDK 等版本代码，不切换其他题库的绑定或题型内容指纹。manifest.assets 声明的静态资源仍参与代码身份，不能用于存放需要受控更新的样例图片。旧普通与样例历史仍使用当时冻结的数据。新制作样例默认编辑、白板、历史全部开启，无需询问。
- **读取不等于迁移。** 未声明版本的旧文件按默认值读取，普通启动不补字段、不升级题型、不修改用户题库。不能为了加入 `requiresApi`、`formatVersion` 或发布元数据改变旧包/已练习题库；这些字段用于新生成的文件。
- **历史使用当时的内容。** 继续使用冻结的题目、页面、答案、评分、笔迹与固定组件版本；缺少快照依赖或遇到不支持的 API 时明确报错，不用当前包代替。
- **更新核心保留用户目录。** 手动更新应先保存并关闭服务，备份整个产品目录，保留根层题库、全部拓展版本和 `.state/`。只有同时恢复匹配的程序和数据备份，才能保证回退；不能让旧程序直接读取已被新程序转换的数据。

## 显式简答升级

根层启动脚本默认不升级题库。用户主动执行：

```powershell
.\Start-QuizForge-Web.cmd -UpgradeShortAnswer
```

才启用既有 `--upgrade-short-answer` 迁移：将已知简答 1.0.0、1.1.0、1.2.0、1.2.1 转到已安装的 1.2.2，支持单题型与混合题库。执行前先保存、关闭同根服务并备份产品目录；运行中的服务或正在启动的同根窗口会使这个开关明确失败。单题型创建新版状态，保留旧历史与旧状态，已有新版状态不覆盖。混合题库在 `.state/upgrade-backups/` 保存原题库和状态的字节快照，然后通过既有编辑事务更新题库与同一状态文件，进行中轮保留其他题型状态，已完成轮的全部答案转为草稿；历史题目与评分内容保留，旧进行中轮标记中断。详细行为见 [核心源码说明](CORE_SOURCE.md#原简答题库升级)。当前没有迁移预览/备份界面或通用迁移工具，启动开关不能替代用户自行备份。

自动保存评分升级另用 `--upgrade-short-answer-auto`，仅迁移 1.2.2 → 1.3.0，普通启动不执行。先保存/取消编辑并关闭服务，再从产品根目录运行：

```powershell
java -jar core/target/quizforge-web-1.0.0.jar --root . --port 8787 --upgrade-short-answer-auto --upgrade-only
```

命令先绑定端口，同端口已运行时拒绝开始迁移；`--upgrade-only` 完成后退出，再普通启动。它不改题目 data/outline 或题库/题目 ID，保留 answer/draft 与已有正式成绩，将已提交 pending 简答转为正式 0 分；完成练习仍 finished，旧冻结历史保持原样，不套用旧升级的“完成答案转草稿”。事务前在 `.state/upgrade-backups/` 保存原 bank.json/state.json 字节。未保存编辑草稿、目标版本已有练习或内容校验冲突时拒绝对应迁移并保留原文件；旧包和旧状态保留。详见 [评分迁移说明](CORE_SOURCE.md#简答自动保存评分升级)。

## 发布验证要求

每次修改宿主公开接口，用之前发布版本的未声明 Manifest、旧单题型/混合题库与冻结历史检查读取、练习、编辑、评分、保存和重启恢复。再检查显式 v1 声明、不支持版本/能力、旧历史缺版本字段及错误提示。对比旧包字节和旧状态的身份/签名；修复失败再发布。当前定向检查的结果不代表已经完成所有浏览器、移动设备或真实模型验收。
