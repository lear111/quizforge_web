# V2 开发流程

适用于 `v2` 分支的全部工作。与本文件冲突的旧约定不再适用。

## 1. 三个角色

| 角色 | 负责 | 不负责 |
|---|---|---|
| 项目负责人 | 决定做什么、不做什么；试用并验收每个功能 | 读代码、读长文档 |
| Claude（审查） | 把需求整理成设计；审查有风险的改动；用大白话解释依据 | 替负责人做产品决定 |
| Codex（实现） | 写代码和测试；如实报告结果 | 自行增加需求或保护机制 |

## 2. 三份文档，只认这三份

| 文档 | 回答什么 | 谁改 |
|---|---|---|
| `V2_ARCHITECTURE.md` | 做什么：全部决定（D 编号）、数据格式、流程 | 只在负责人做出新决定时改 |
| `V2_WORKFLOW.md`（本文件） | 怎么协作 | 负责人同意后改 |
| `V2_PROGRESS.md` | 做到哪了，一页 | Codex 每合并一个功能后更新 |

其他文档（v1 计划、测量报告、被否决的设计、长篇设计说明）全部放在 `core/docs/design/archive/`，仅作记录，不需要阅读。各 PR 的记录放在 `core/docs/design/reviews/`，每份不超过一页。

## 3. 每个功能走同一条路

功能按"负责人能亲手试用的一件事"来划分（见第 6 节的清单），前后端一起做。

```
① 说明   → ② 实现   → ③ 检查   → ④ 试用   → ⑤ 记录
负责人确认   Codex     CI + 审查   负责人     Codex
```

**① 说明（开工前，半页以内）**
Codex 用大白话写清：做完后负责人能做什么；不包含什么；有没有需要负责人决定的事。写在 `V2_PROGRESS.md` 该功能的条目下。没有待决事项就直接开工；有就等负责人答复。
历史、考试、AI 评分这三个功能另附不超过两页的技术设计，由 Claude 审查后开工。

**② 实现**
一个功能可以拆成几个 PR，每个 PR 只做一件事。

**③ 检查**
- 所有 PR：CI 三个 job 全绿。不跳过、不删除、不放宽测试。
- 高风险 PR（见第 4 节）：等 Claude 审查通过才合并。
- 其他 PR：CI 全绿即可合并。

**④ 试用**
功能合并后，Codex 给出试用步骤（怎么启动、点哪里、应该看到什么，五步以内）。负责人试用后回复"可以"或指出问题。负责人说可以，这个功能才算完成。

**⑤ 记录**
更新 `V2_PROGRESS.md`：状态、实测速度、遗留问题。

## 4. 高风险改动（必须审查）

- 作答的保存、锁定、分数保存、重做
- 历史和考试记录的存储
- 写入题库文件（编辑器、导入）
- 什么时候把答案（`solution`）发给前端
- 题型页面和评分环境的沙箱
- 登录鉴权和局域网访问

## 5. 决定权

**必须先问负责人：**
- 新增或去掉一个用户能感知的功能或行为。
- 新增任何"保护机制"：一种检查、一层缓存、一种兼容处理、一个限制。提出时必须用一两句大白话回答三个问题：防的是什么情况？不做会怎样？代价是什么（速度、复杂度）？
- 改动 `V2_ARCHITECTURE.md` 中的任何决定。

**Codex 可以自己定：** 代码结构、命名、测试写法、不改变行为的重构。

**原则：** 负责人看不懂的设计，默认是设计的问题。能用几句话讲清依据的才保留。拿不准时选更简单的做法。

负责人做出的每个新决定，由 Claude 写入 `V2_ARCHITECTURE.md` 并编号。口头说过但没写进去的不算数。

## 6. 功能清单与顺序

每一段做完，负责人都能亲手用到新东西。

| 段 | 做完后能做什么 |
|---|---|
| 1 | 打开题库，看到大纲，做一道单选题，提交并看到分数 |
| 2 | 多选、判断；草稿自动保存、白板、重做；切换题库并回到上次位置；刷新 |
| 2.5 | 题型接口定稿；清点并删除 v2 不再使用的 v1 代码和测试。不做题库转换工具：负责人的题库由专门的对话直接改写成 v2 格式，开发期间继续用模拟题库测试 |
| 3 | 完成练习、汇总、历史 |
| 4 | 考试模式 |
| 5 | 简答题、AI 评分、人工改分；设置。带答题区的题型另行设计，排在本段之后 |
| 6 | 导入导出、Hub、题库编辑器、拓展开发模式 |
| 7 | 打包发布、整体性能复测 |

顺序可以由负责人调整。

## 7. 汇报格式

Codex 向负责人汇报时不使用内部编号和术语，固定四行：

- **现在能做什么**
- **怎么试**（五步以内）
- **实测速度**（只列用户能感知的操作）
- **需要你决定的事**（没有就写"无"）

## 8. 不变的底线

- 后端不执行题库或拓展制作者提供的代码。
- 答案锁定之前，任何接口的响应都不包含 `solution`。
- 保存失败时不留下写了一半的数据。
- 不使用负责人的真实题库和真实数据，除非有明确授权。
- `main` 保持 v1，除严重缺陷修复外不改动。

> 补充：磁盘上的数据结构及其设计理由记录在 [V2_DATA_STRUCTURES.md](V2_DATA_STRUCTURES.md)。改动数据结构前先改该文档。
