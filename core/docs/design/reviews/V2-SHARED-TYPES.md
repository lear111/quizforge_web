# E：共用数据定义与后端类型检查（开工说明）

**状态：待审查，只写方案。** 基于 `v2` 的 `667d824`；#140 已审查合并，任务 D 完成。以下实施分两次提审，不在本 PR 写实现。

**定义放哪、用什么形式。** 使用纯 TypeScript 声明文件，不生成代码、不增加运行时库：

| `core/shared/v2/` | 唯一负责的定义 |
|---|---|
| `json.d.ts` | JSON 值与对象；题型自定的内容保持不透明，外来数据先为 `unknown` |
| `bank.d.ts` | 已实现的题库、大纲、大题/小题与听力结构 |
| `state.d.ts` | 当前作答、评分结果、回执、独立笔迹文件；复用 `answered.d.ts` 的大纲状态 |
| `api.d.ts` | 每个已实现接口的请求/答复及公共错误，引用上述定义，不重复字段 |

前端 `api/` 用 `import type`，移除目录、题目、大纲等就地重复定义；组件与 store 的 Ref、DOM、忙碌状态仍留前端。后端保持 JS，以 JSDoc 的 `import(...).类型` 标注参数和返回值；快照的 Map、缓存、磁盘路径等内部结构放后端自己的声明中，不混入共享传输结构。请求体和解析出的文件先按 `unknown` 接收，由既有检查缩窄，不因类型注解直接信任输入，也不新增运行时检查。

**检查范围与接入。** 新建 `core/tsconfig.server-v2.json`（`allowJs`、`checkJs`、`strict`、`noEmit`，NodeNext），先覆盖全部 controller/service/repository（当前 1/8/9 个 JS 文件），加 `typecheck:server` 并接入 Windows、Ubuntu 的 Checks。按需补 Node 24 / Express 5 的开发用类型包。导入的 utils/V1 工具仍会被编译器追踪，不能靠 `exclude` 隔离：只为实际调用的出口补准确声明边界，其实现留后补；不得用同名声明遮住上述 18 个受检文件，也不使用全局 `any`、忽略错误或关闭严格检查来过关。

**如何忠于现状。** 笔迹保存实际只返回 `{inkRevision, state}`，单题写答复可省略笔迹；共享定义必须区分这些答复，纠正前端把所有保存答复都标为完整题目的写法，不改线上字段。只定义已经实现的接口，不提前实现文档中的 `practice/` 存放迁移、历史、考试、AI 或带分数评语；发现无法仅靠注解解决的行为/文档冲突，单列问题提审。JSON 字节、数字字面量元数据、原子写入、冻结、回执、错误码、权限、solution 发送时机、沙箱和启动空白行为均不变。不开始任务 F 的动作收口与长函数整理。

**实施与验收。** ① 共享声明、前端引用及编译期契约用例；② 后端逐层 JSDoc、工具出口声明与 CI。用正反类型用例覆盖请求必填字段、笔迹精简答复、评分结果及作答文件，确保错误赋值确实被拒绝；既有运行时校验与所有测试断言不改。每次提交运行 UI/后端类型检查、构建、完整测试、质量与浏览器检查；必须五项 CI 全绿再等审查。此方案不涉及速度优化，不声称有性能收益。

**本 PR 验证。** 仅新增本说明并更新进度，未改代码、依赖、测试或构建成品；文档链接与差异检查通过。仓库对纯文档 PR 跳过 CI，本 PR 不把未运行的 job 标为通过；后续实现按上面的完整门槛验收。
