# S1：只读状态文件体积统计

## 改了什么

基于 main `a31b08412bc64db533b9cc7259fa782269c41f9d`（#48 已合并）。B2b 候选 B 未批准，B2b 仍暂停，待负责人自行运行真实数据统计后再定方向。本 PR 不假定合成数据代表真实用户。

新增 `core/scripts/dev/inspect-state-sizes.mjs <数据根目录>`：只扫描 `.state/<64-hex>.json` 和 `.development/.state/<64-hex>.json` 的普通文件。它只读、只输出 JSON Lines，不启动服务、不联网、不迁移、不修复、不创建目录/文件。跳过符号链接/目录联接、备份、配置、资源和其他非练习文件。

每文件输出：哈希文件名、固定 scope、实际文件字节、修改时间、题数/有当前记录题数、现代轮数/字节、旧 history 条数/字节、全部已知 receipts 的条数/字节、全部 draft 字段的字节、当前单题最大笔迹、回执最多的当前题的条数/字节、答案结果与剩余字节，以及前后 SHA-256 和一致性结果。末尾输出文件数、min/median/P90/max、互斥类别总字节及百分比。P90 用 nearest-rank；空集为 null。

先完成所有文件的读/哈希，再做第二轮哈希和文件集合检查。不能把这一观察称为文件系统隔离快照：建议停下并发编辑再运行；检测到改变或无法验证时退出 2。坏 JSON 仍记录“无法解析”、字节数及可获取哈希，继续其他文件；根目录不可读仅报通用消息、退出 1，不泄露异常/路径/内容。

所有 JSON 字节使用 parseJson / jsonBytes；原始数字存在父对象的 numericSources，所以原始子值用 projectJson(parent,[key]) 减去键/分隔符计量。连原始 answer=1.0 / result=2e0 也保留三字节，不误算成各一字节。

## 计数口径、兼容性与隐私

“全部”receipts/draft 指全树字段出现量，包含历史和回执内的副本，可能互相重叠，不相加作占比。已知 receipts 容器包括 receipts、finishReceipts、restartReceipts、completionReceipts、editReceipts；没有执行内容中的规则或链接。

用于占比的 categoryBytes 独立分区：顶层 historyRounds / history / upgradedCompletion 先取得其整棵子树；其余树上 receipts 容器优先，然后 draft，然后 answer/result；不再下探已归属子树。other 包含剩余数据、键、标点和源文件格式空白，unparsed 包含坏文件实际字节。各项之和精确等于所有文件大小。breakdown 将它投影成 A1 的 receipts / ink / history / other 四类。

“有当前记录”是状态 draft/submitted 或存在非空 answer/result/draft 或回执；单独 revision>0 不算。最大单题数只看当前 questions，不返回题 ID；相同回执条数时以编码字节选最大。空数组与 null 字段包括其 JSON 编码成本，非空单题笔迹才进入最大值。

输出不包含正文、答案、标题、collection/stateKey、题 ID、完整路径、用户名、异常栈、令牌或其他内容。mtime 和哈希文件名按任务要求保留。统计脚本不负责判断任意配置项是否符合业务 schema，只要求可解析的 questions 对象；绝不为看统计而调用 StateStore.load（它原有的开发态适配可能写盘）。读取可能触发 OS 的 atime 策略，不修改内容或 mtime。

## 明确没改什么

没有改业务逻辑、HTTP 响应 JSON/状态码、规则输入、版本号、回执、持久化格式、事务、配额、历史算法或四份标准答案；没有实现 B2b，没有读取作者真实数据，没有启动日常服务或远端服务，没有访问 SSH。B7a 在另一独立分支/PR，不混入本 PR。
