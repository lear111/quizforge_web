## 改了什么，没改什么

- 提交的 REVISION_CONFLICT/ANSWER_LOCKED、评分的 RESULT_CONFLICT/SUBMISSION_STALE 均读取胜出状态并更新同一 iframe。除 401 外所有 4xx 放弃过期请求，413 明确显示“作答文件已达上限”；网络/401/5xx 保留原输入及原请求重试。INVALID_RESULT 上报无法评分的原逻辑保留。
- `whiteboard.ts` **直接挂载 V1 whiteboard.js 与 CSS**，并复用全屏控制器；只新增宿主布局/生命周期适配和 TypeScript 声明，未修改画笔、橡皮、选区、相机、停靠及其内部文件。固定草稿坐标宽 760，首次草稿沿用 V1 的 24px 留白适宽相机；全屏沿用隐藏侧栏/页头的宿主布局，练习视图保持原来的响应式布局；草稿模式返回作答后隐藏区外笔迹，再回草稿恢复。V1 的 answer-ink/channel 依赖仍在打包图内，但 V2 不注册答题区、不接通该通道，全部宿主笔迹只写 ink，不评分。
- 答案/笔迹/评分共用串行队列，首次实际发出才固定 revision、requestId、正文；失败重试逐字节相同。评分成功在释放队列前发布新 revision，同题 context 更新前先保存已排队笔记；普通保存确认不重载题型、不覆盖较新输入。停笔 1.5 秒、连续最长 10 秒，切题/切库/提交/刷新先 flush；忙碌/恢复期间禁止新的界面输入。锁后草稿仍可写，重做清当前题活跃内容，历史不改。
- `.qf-v2/position.json` 独立原子保存题号，不走 state.json 事务或修改作答 revision/回执；每次打开直接读取，位置失效回第一题，移动题库时随文件带走，文件损坏报错保留。复用现有受检路径与读取上限。前端仅用新的 V2 localStorage 键记上次题库，切库优先恢复本窗口记忆的题号（另一窗口改过持久位置也不串位）、浏览器刷新恢复题库和位置；显式刷新保留现题，删除时回退。
- `server/host/v2/timing.js` 是独立、可关闭的互斥 Server-Timing 诊断，不改 V1 timing 分段、评分校验、响应正文、solution 发送条件、state.json 格式或标准答案。未做笔迹存储拆分、④基础库题型迁移、听力、历史、AI、安装包；不使用真实题库、不动日常服务、main 或服务器。

## 保存诊断（先测再接白板）

Windows 11 10.0.26200，i5-13500H，Node 24.13.0；独立合成根、随机回环端口，2 次预热后各 n=30。命令 `node core/scripts/dev/measure-v2-ink-save.mjs`。50 题每题 200 笔、每笔 8 点；每行是保存一次选项，不把全部 ink 放入 HTTP 请求。

| 状态 | 写入字节 | 解析 | 校验/组装 | 序列化 | 原子写盘 | 后端总 中位/P95 | 客户端 中位/P95 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 小状态无笔迹 | 870 | .095 | 11.885 | .212 | 6.154 | 18.751 / 39.647 | 23.471 / 48.345 |
| 50×200 笔 | 3,176,668 | .225 | 104.069 | 310.811 | 24.369 | 472.647 / 835.386 | 500.291 / 853.957 |

单位 ms。校验/组装包括快照绑定、状态候选构造与冻结，嵌套序列化/写盘从中扣除；序列化包括状态与响应，解析仅 JSON 解析，收请求和响应发出等待不算其中。后端计至响应字节构造完成，不含客户端读取/绘制。各分段分位数不相加。测试脚本同步钩子测到两组均每次 1 个文件、1 次文件 fsync，无目录 fsync；小/大状态文件 write 为 .286/3.232，fsync 为 1.258/9.547，rename 为 1.627/2.943 ms（均中位，已包含在原子写盘中，不能重复相加）。其余约 .465/.703 ms。

**结论/待议**：原先 PUT 约 31 ms 不是单由 fsync 导致；合成大状态超过 #69 的 30 ms/1 MB 评估门槛，主要增长来自全状态序列化与组装。本 PR 保持已审定布局，不擅自拆存储；后续是否拆 ink 请审查决定。以上为一次环境的诊断样本，不是真实题库或性能承诺；钩子本身开销未独立量化。
