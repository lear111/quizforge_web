# V2-P1-1：独立启动、只读快照与两级结构检查

## 问题与改动后的行为

设计 #59 已合并至 `v2`（2217b28）。本 PR 实现其第 7 节 P1-1：新服务不加载旧规则引擎，不读取 v1 的 `.state` 或设置，通过 `/api/v2` 提供目录、概览、一道题及受限资源。根页面明确提示 V2 界面尚在 P2 开发，尚不能进行作答。

PR 目标为 `v2`，不是 `main`。工作目录固定为 `C:\dev\quizforge-web-v2`；没有修改旧日常目录、连接部署站点或访问负责人真实题库。只创建自动清理的临时合成数据根，监听回环随机端口；不占用 8787/8788。

### 明确没改什么

- 不实现 P1-2/3 的保存、提交、评分上报、重做、位置、刷新事务；这些路由返回 501。P3/4/5 的历史、考试、AI、导入导出和编辑器同样没有实现，不回退到旧规则接口。
- 不修改 v1 响应、状态码、规则输入、版本号、回执、持久化格式或任何现有标准答案；新接口有新响应，不能用 v1 前端调用。
- 不迁移基础题型、用户题库、笔迹、历史或设置。现有基础题型仍是 v1，迁移在 P2/P4；合成页面不是可供人工做题的演示题库。
- 不执行或 import `practice.js`、`grade.js`、schema；不运行规则子进程，不构造 validationEnvironment，不使用校验缓存。
- 不制作安装包、不更新 `QuizForge.exe`。旧入口仍为旧测试留档，物理删除和统一启动/打包清单在 P1-4，不能把旧 exe 当成本 PR 的 V2 启动器。

## 读取接口与数据投影

表中 B 为 `/api/v2/banks/{bankId}`，Q 为 `B/questions/{questionId}`。

| 接口 | 本阶段行为 |
|---|---|
| GET `/api/v2/health` | apiVersion:2、phase:P1-1、只读 availableFeatures；不扫描题库 |
| GET `/api/v2/catalog` | 从 question-banks 的物理分组/题库目录读取最少元数据；坏 JSON 仅该条目 unavailable，不打开题库 |
| GET `B/overview?questionId=…` | 打开边界：银行文件/资源树、所用拓展和声明的 SDK 检查；返回分组大纲、听力 id/title、questionTypes、未作答状态及一道初始题；坏初始题为 initial.error，整体仍 200 |
| GET `Q?snapshotId=…` | 只用已打开快照，惰性检查该题；solution/answer/draft/ink/submission/result 均 null；普通模式零目录扫描/零 lstat |
| GET `Q/assets/{assetId}?snapshotId=…` | 只允许本题 question 中 qf-asset 引用生成的标识，不扫描 solution；读出时仍检查真实路径/身份/大小 |
| GET `B/listening/{id}?snapshotId=…` | 只允许大纲已引用的材料。本地支持 Range/HEAD；http(s) 只返回 kind:remote/src/title，不后端请求远程地址、不在打开时预加载 |
| GET `/api/v2/extensions/{artifactId}/manifest`、`/files/{fileId}` | 仅已打开快照绑定工件；manifest 仅投影必要字段，入口用 alias；页面/代码作为字节返回，不执行 |
| GET `/api/v2/sdk/{component}/{version}/{relative…}` | 只允许已打开工件明确声明的组件/版本；受检相对路径，不提供整个代码根的任意文件服务 |

`questionTypes:[{questionId,type}]` 补足总体设计 4.1 第 4 步的“每道大题 type”，类型缺失时为 null，不提前让整库失败。所有题状态暂为初始默认值，lastQuestionId:null、pendingGrading:[]；读取已有 v2 状态及位置在 P1-2，绝不拿旧状态冒充。

bankId 当前为物理相对目录哈希，sourceId 是作者 id，两份同 sourceId 不合并；snapshotId 含 bankId，不能串用另一实例快照。P1-1 没有实例文件，不许把这个路径定位规则当成已经批准的重命名持久身份方案；P5 再定实例移动。snapshotId 由完整检查结果决定，未变化再次 overview 不废止令牌。每题 fingerprint 仅含 questions.<id> 整块和大纲条目，素材、听力表、拓展代码的变化只更新快照，不改每题 fingerprint（Q10）。

### 错误和安全

- 重复键/非法 UTF-8 JSON：400 JSON_DUPLICATE_KEY/JSON_INVALID，位置 offset/line/column，无内容片段；打开结构错 422 BANK_STRUCTURE_INVALID，旧格式 422 BANK_FORMAT_UNSUPPORTED。
- 坏单题只返回该题错误：缺记录 QUESTION_NOT_FOUND 404、缺类型 EXTENSION_NOT_FOUND 404、非对象 question/solution 为 QUESTION_INVALID 422；小题内容与大纲不一致不在后端检查。
- 拓展歧义 EXTENSION_AMBIGUOUS 422（matches），不选最新。入口/SDK 不安全或缺失仅影响使用它的题。
- 文件项目包含根、目录、文件；遇到第 1001 项即停止，422 FILE_COUNT_LIMIT，details:{lowerBound:1001,limit:1000}，中文说明“至少 1001 项，上限 1000 项”。不作第二次计数。
- 完整响应全文搜索唯一 solution 标记；solution-only 引用不在资源表，猜 assetId、跨题/跨快照均被拒绝。`bank.json` 不能当可见资源或听力读出；没有整个题库静态目录入口。
- 路径逐段拒绝绝对路径、越界、反斜杠、盘符、保留名和重定向；资源实际读取继续 FileCache 前后身份核对、O_NOFOLLOW/fstat。直接访问作者 HTML 响应带 opaque-origin sandbox CSP，不让其成为宿主同源页面。
- 回环默认可用；非回环监听必须显式给新 token，API 用 x-quizforge-token，不读取旧 LAN 密码。Host、Origin、Sec-Fetch-Site、转发头均检查；新网络设置 UI/认证适配在 P4/P1-4 再接线，当前不伪称完整 LAN 配置已迁移。

## Q2 的 manifest / 开发对象具体提案（本 PR 只读协议，待本 PR 审查确认）

```json
{
  "id": "quizforge.single-choice",
  "version": "2.1.0",
  "name": "单选题",
  "apiVersion": 2,
  "entries": {
    "practice": { "html": "practice.html", "js": "practice.js", "css": "practice.css" },
    "grade": "grade.js"
  },
  "sdkVersions": { "richtext": "2.0.0", "answer-area": "2.0.0" },
  "development": false
}
```

version 是完整版本，type 的 @2 仅匹配其 major。四入口必填，必须是拓展内普通文件。sdkVersions 默认 {}，仅 richtext/answer-area/ink；组件版本为三段数字，读取同一精确版本。P2 不得把上面示例当成真实 SDK 已实现。静态入口 alias 由宿主提供，不允许调用方指定任意文件路径。

开发模式提案：仅显式 CLI `--development`（不读取 v1 设置），并且该拓展 manifest 的 development:true 时，每次 Q GET 重新检查此拓展，更新 artifactId；普通拓展仍只在 overview 检查。不自动按目录名猜开发对象。新 token/新开发设置 UI 在后续阶段。本 PR 不实现旧 grader 任务失效/恢复（尚无 grader），相关隔离 P2/P5。

## Q5 字段与默认值 / 读取常量

| 字段 | 必填 / 默认 / 本阶段检查 |
|---|---|
| bank.formatVersion | 必填，2 |
| bank.id、title | 必填，非空字符串；id 最长 120，title 最长 200，不自动生成 UUID，不把两个 sourceId 相同实例合并 |
| description | 可选，默认空字符串 |
| features.history / exam | 可选，各默认 true；若提供必须布尔值 |
| outline | 必填数组，可为空；分组 title/items 必填；大题 id 全库唯一，小题 id 在本大题唯一 |
| 大题自身 label/maxScore 或 parts | 恰好一个形态；parts 非空；label 非空≤200；maxScore 正有限数；parts 总分用 decimalSum |
| listening | 可选；只检查被引用项的 title/src。src 为安全本地相对路径或 http(s)，不后端下载 |
| questions / record | 不做全表类型内容检查；访问大纲题时才验证记录存在、question/solution 为非数组非 null 对象、类型可唯一解析 |
| question / solution 内部、额外字段 | 不跑 schema，不比对 parts，不解释内容；question 中 qf-asset 字符串仅做资源路径处理 |
| ID | 字符串 1–120，拒绝控制符、斜杠/反斜杠；纯数字字符串合法，顺序来自 outline 数组 |

| 读取常量 | 数值 / 口径 |
|---|---|
| bankBytes | 8 MiB bank.json；现有 JSON 读取量级，不是状态文件预算 |
| manifestBytes | 64 KiB |
| assetBytes | 64 MiB/文件；含本地音频、资源；Range 仍通过受检文件读取，不因此请求任意外部地址 |
| treeItems | 1000/被检查树，含根与目录；超限 lowerBound:1001 |
| JSON 深度/字符串/数字字面量 | 复用现有 parseJson：64 层、字符串 2,000,000 字符、数字字面量 100 字符；解析拒绝重复键与非有限数 |
| 文件正文 / 摘要缓存 | 复用 K2 默认值：正文 256 条/32 MiB，摘要 8192 条/64 MiB；命中仍核对身份，不在普通 Q GET 发起全树检查 |

写入常量仅提案，不在本 PR 实施：request/body/answer/draft/ink 上限、32 MiB 状态、64 MiB 状态缓存、回执数量/期限、requestId 长度、锁版本/结果约束等须在 P1-2 的 reviews 确认后使用。不得误把读取 assetBytes 当成已批准的答案体积。

## 新增用例与兼容性验证

测试文件 `core/test/v2/readonly.test.mjs`，12 项顶层用例（各含多组 HTTP 断言）：

## 实测方法与结果

命令：`node core/scripts/dev/measure-v2-readonly.mjs 30`。全部使用临时合成根，20/200 题各 30 个新 Node 进程，回环随机端口。每个进程：启动 → health 可响应 → catalog 发现 bankId → 首次 overview → 再次 overview → 单题 GET → 退出；计时 performance.now()，直到 JSON 正文读完。startup 含进程创建与一次 health 往返，不含 catalog；first overview 之前已读 catalog 元数据，此事实不称“完全磁盘冷缓存”。OS 页缓存不清空。没有规则子进程、浏览器渲染或真实用户数据。中位数为中间两值平均，P95 最近秩。

待本次本机测量完成后填写实际数字；不使用 V1 的耗时作 V2 实测。
