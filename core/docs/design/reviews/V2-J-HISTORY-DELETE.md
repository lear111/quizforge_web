# J：删除单轮历史记录

状态：[PR #184](https://github.com/lear111/quizforge_web/pull/184)，待审查。目标分支 `v2`；不合并，不开始 K。

## 改了什么

- 新增 `DELETE /api/v2/banks/{bankId}/rounds/{roundId}`。成功为无响应体的 204；已清理的同一轮可重试。无批量入口。
- 历史浮层每项增加独立删除按钮。确认框写明完成时间和得分；取消不发请求，成功立即移除该行，失败保留并显示错误，可再次操作。正在回看的那一轮禁用删除，删除按钮不触发进入回看。
- `history-delete.repository.js` 负责全树预检、删除标记和单轮清理；`history.repository.js` 和历史服务统一过滤标记，归档题目、素材、笔迹及缓存中的历史拓展入口不能再访问该轮。路由及控制器沿用既有权限与错误响应。
- 前端 API、Practice Store 和历史菜单分别负责发请求、限定当前题库和更新浮层，没有引入新的路由状态。

## Tombstone 和崩溃恢复

标记路径是 `.qf-v2/rounds/<小写 UUID>/deleted.json`，内容为 `{"formatVersion":1,"roundId":"<同目录的 UUID>"}`。严格解析字段、版本和轮次。目标由题库索引、合法 UUID 和真实目录共同限定，排除 `prepared` 候选。写前检查整个目录树；每次移除前再检查规范路径、目录/文件类型和已观察的身份。只逐项 unlink/rmdir，不递归删除父目录，不跟随链接。

1. 预检或标记原子写入失败：未开始清理，仍可打开原轮。坏 bank/state 不妨碍预检；仅在路径安全时允许显式删除。
2. 标记完成：只读、笔迹和素材入口立即视为已删除。先后删除其余内容，保留标记。清理失败返回 503；再次 DELETE 可继续，列表也尽力清理残留，失败时仍隐藏该轮。
3. `recoverRestart()` 识别合法标记后保留原 `roundId` 代际，不要求已删除的三个归档入口仍存在。删除不改写 `restart.json`；正常归档及其原有回滚仍可登记或还原回执。原请求重放不会二次归档。标记损坏或不匹配时不能当作有效删除。

## 明确没改什么

未修改当前练习、其他历史轮次、归档存储格式、归档事务提交点、作答/评分/白板语义、版本冲突和路由。未新增索引、批量删除、全库自动清理、考试或 AI。测试只用合成夹具或基础题型的临时副本，独立回环端口；未操作真实作答。

## 兼容性与测试覆盖

- 删除非最新和最新轮，核对 204、重复 DELETE、列表过滤、该轮读写 404、当前 state/ink、其他轮次与原回执字节一致。
- 删除当前回执对应轮次后使用新库实例打开，重发旧请求，再归档；另测新归档 `published` 阶段失败时回滚到已删除的上一轮代际。
- 真实子进程在移除首个文件后退出；列表续清理。模拟标记 rename 失败、标记后清理失败、归档损坏及错误标记。
- 校验非法编号、题库不存在、回放中的 prepared 候选、目标与子目录链接（Windows junction、Ubuntu symlink）、预检后目录更换；原文件与目标外夹具保留。
- 既有 completion 浏览器探针追加桌面和手机流程：正在回看不可删，确认显示时间和分数，取消不发请求、错误时可重试、成功后浮层移除，当前练习 URL 和文件字节不变。继续保留历史答案、评分不可写及白板权限的断言。

## 风险与限制

- 标记需要保留，不能手动清除它来节省空间。它不包含用户内容，每个已删除轮次只保留一个小文件。
- 同步预检及逐项复核能拒绝一般的链接和目录替换，但不是针对另一同权限进程持续竞态改写本地文件系统的内核隔离。沿用现有文件 fsync + rename，不增加目录 fsync，未做断电和真实移动设备验收。
- 如果文件因权限或外部锁不能清理，轮次维持隐藏，不阻塞当前练习；再次 DELETE 能得到明确错误。历史列表只尝试清理已经有合法标记的轮次。其他标签页已显示的内容不会被远程回收，后续请求按删除状态处理。
