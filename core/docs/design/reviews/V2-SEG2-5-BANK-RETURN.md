# V2 第 2.5 段：切回题库浏览器测量

只改测量工具：在临时回环服务中加载由同一 Vite 配置生成的内存构建，通过断言唯一的源码锚点记录前后边界。没有修改正式代码、构建产物、API、缓存或存储。沿用 #91 的两份合成题库（各 3 题，起始题含一张图），预先打开 A/B，再测 B→A；每组预热 2 次、取 30 次。每次检查选项可交互且图片已加载。Windows 10.0.26200、i5-13500H、Node 24.13.0、Chrome 157.0.8103.39，桌面 1440×900、手机视口 390×844（同一台机器）。

**单位 ms；中位数 / P95。** 主链按同一时钟对齐，单样本差额 P95 ≤ 0.41 ms；分段分位数不能相加。

| 区间 | 桌面，缓存开 | 手机视口，缓存开 | 桌面，缓存关 | 手机视口，缓存关 |
| --- | ---: | ---: | ---: | ---: |

富文本脚本行包含 blob 构建、浏览器调度和求值，不能把整段当成纯 JS CPU 时间。双 rAF 表示经过一次绘制机会，不是合成器实际呈现时间；它与宿主就绪区间重叠，不计入总和。缓存开启时每轮六个题型/SDK 响应与一张图均命中 Chromium HTTP 缓存，概览未命中；关闭对照没有命中。未插桩缓存开对照：桌面 216.0 / 297.0、手机视口 206.8 / 273.1。插桩轮总中位数分别高 8.4 / 14.0 ms，跨轮差异包含运行波动，不能当作纯插桩开销；桌面插桩组高尾集中在概览阶段。

**结论：** 暖缓存下概览请求是最大的单段，其次是建 iframe 与 SDK 脚本加载；合成起始题的 load 本身约 5 ms。缓存已经省下富文本网络读取，但并不消除每次建题页和在新页面执行 SDK 的代价。本次只定位，未改变切换行为。真实题库、真机与高负载表现未测。

复现：以 Playwright 的 `index.mjs` 为第一个参数运行 `node core/scripts/dev/measure-v2-bank-return.mjs <playwright/index.mjs>`；依次跑 `--phases`、无选项和 `--phases --no-resource-cache`。结果写入忽略目录 `.temp/`。验证：三组 180 个测量样本通过浏览器断言，无页面异常；无新生产用例；CI 见本 PR 检查。
