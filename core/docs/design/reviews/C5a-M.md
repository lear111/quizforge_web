## 2. 非重叠计时边界

只在隔离诊断代理提供的四个 JS 响应中注入探针；磁盘上的生产文件不变。HTTP JSON/图片/SDK 响应内容不改。代理保留状态码并缓冲响应，浏览器仍保留正常 HTTP 缓存；不用 Playwright route，以免其关闭 HTTP 缓存。它转发到固定 loopback 服务，并将自身同源 Origin/Host 映射到该内部地址，不提供任意 URL 代理。

宿主使用 performance.now()；iframe 探针用 performance.timeOrigin+performance.now()，归一化到宿主时间原点；按目标 qid/session 匹配，不用消息到达时间代替 iframe 内执行时间。主机计时精度约 0.1ms，跨 timeOrigin 的浮点表示存在亚毫秒量化，因此表格的小数不表示微秒准确度。

| 阶段 | 起止与归属 |
|---|---|
| a | navigateQuestion 中进入 flushPane →其返回。内含页面 flush、白板 saveInk 与 writes.settled；子表是 a 的明细，不再加进总和。 |
| b | 本次 showQuestion 的 loadQuestion 调用→返回：包括应用缓存复制、待定预取等待，或条件重验证的请求/响应与 JSON 处理。 |
| c | pagesCache.load + prepareAssets（含 SDK 缓存/请求）整体开始→返回。题目内容图片由 iframe onLoad 请求，计入 e，不重复计入 c。 |
| d | mountExtension 调用前→页面调用 QF.page.register：拆成 d1 调用前→首段内联脚本开始，d2 首脚本→register。包括 srcdoc 准备/解析及 SDK/题型顶层求值。 |
| e | register 调用→await load(context) 完成、发送 registered 前。真实题型 onLoad 等待富文本 view.ready/图片；不是只等 DOMContentLoaded。 |
| f | onLoad 完成→registered 交付、宿主销毁旧 iframe/加载白板/更新大纲，直到 pane 非 inert/loading 后的跨帧稳定终点。它包含浏览器帧等待，不能全算作宿主 CPU。 |
| g | 每条 total−(a+b+c+d+e+f)，含按钮回调、前后胶水等未覆盖区间；不是再次计入某段。 |
| total / loadMs | total 从按钮 click 捕获开始，到上述稳定终点；loadMs 原样读取 pane.dataset.loadMs，仅覆盖 showQuestion，不包含前置 flush 与稳定等待。 |

稳定终点明确采用：首次 rAF 检查 pane 可交互，随后两次 rAF 确认；这比“首个新内容下一帧”更保守。未用截图推断物理显示时刻，也未从结果里减去估计的一帧。无法从已有记录恢复单次 rAF 首帧数值；这是当前测量口径的限制，不应把 f 当作纯同步收尾耗时。

| 模式范围 | 首轮仅考虑普通、未提交练习页；考试、历史、编辑器、已提交查看继续原路径。不得带着练习能力/上下文进入历史或考试。不是本次新增限制，仍须单独设计和审查。 |
| 主要风险 | flush 后候选过期、A→B→C串写/迟到状态、后台布局污染、资源配额与URL泄漏、CPU/规则/图片争用使前台反而更慢、上下文变化导致命中率低。需要失败回退原 showQuestion，并保存旧题输入，而不是强行激活过期 iframe。 |

结论：预建的额外上限主要是 e，c 已大多被现有预取覆盖；它仍需一个“后台页面不得产生副作用”的可信契约。不能把它当成完全无协议成本的替代方案。本报告不决定实施哪一个。

## 8. 瓶颈判断、限制与审查问题

1. 干净切题中，d 的中位数约 71–75ms，是本次最大的单阶段；当前 total 中位数约155–163ms，能确认 iframe 重建确实占可见份额，而非只凭源码猜测。
2. 有新输入时，a 成为主要瓶颈：小状态约224–244ms，大状态约672–731ms；总中位数约415–443ms与900–995ms。预建/复用都不会消除写队列保存等待，不能据此承诺大状态下切题降到几十毫秒。
3. 只省d的中位数上限约58–75ms；省c+d+e约82–110ms。收益与代价应据此重新审查；没有足够证据直接批准高风险的API1.6/全部题型改造，也不擅自批准预建。
4. 未精确测量物理首帧/触控输入延迟、首次打开题库、全局CPU/GC归因、移动设备、长期预建内存，以及未来方案的真实命中率和并发副作用；没有用估算补这些空白。真实题型onLoad承诺与实际屏幕首帧仍是两个概念。
5. 首次/再次UI访问与缓存冷热独立；完整矩阵已保留现有预取，额外冷测试会改变缓存条件，因此单列，不混入72组。笔迹场景在草稿模式，其余在练习模式，不将差异完全归因于“多一条线”。
6. 每个30条组保留长尾；没有随机化主矩阵顺序，控制组也不足以归因微小差别。统计不是置信区间或未来设备的性能保证。rAF稳定终点和诊断代理的限制见第2、5节。
