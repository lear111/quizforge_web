# V2 第 2.5 段：静态题页可行性验证

用公开的基础题型展示库 7 道原题，在独立回环服务中实际提交并由原评分环境评分（6 道正确、1 道错误），用“已锁定、不可提交或重做”状态渲染并展开解析。探针专用构建把采集函数注入现有题页运行时，经同一个消息通道交回宿主；固定表单当前值、把画布转为 PNG、把临时图片 URL 还原为 `qf-asset:`，再过宿主白名单。内存里的 HTML 和 CSS 在另一个不允许脚本的沙箱 iframe 回看；宿主只用已取回的位图补图，回看框不发起网络请求。本 PR 不改生产代码、题型、接口、存储、沙箱或归档流程。

Windows 10.0.26200、Node 24.13.0、Chrome 157.0.8103.39；视口 1440×900、390×844。题目区域共 **14 对截图尺寸与 RGBA 像素完全一致（0 差异像素）**。公式保留原生 MathML，无需携带额外公式字体或请求字体文件；比对了 17 个公式节点的尺寸、7 个表格、1 张图及整体排版。单选、多选、判断的选中值、禁用状态、得分及“回答正确／错误”均与原页一致。

| 7 题合计 | **14,922 / 4,999** | **3,688** | — |

每种题型的 CSS 各 **1,228 / 621 B**，同题型只算一次；共用富文本 CSS 另计 **7,031 / 2,159 B**。gzip 值为各项独立压缩的大小。每题每尺寸 1 次；首题包括下载题型文件和创建 iframe，同题型的后续 4 题复用当前 iframe；时间包含必要图片请求、渲染及白名单处理，不含截图或评分。单次探针时间不代表稳定性能指标。

**验证与边界：** 桌面及手机视口均测试了 `script`、`onerror`、`javascript:` 链接、`iframe`、`object` 和外部图片；白名单移除活跃内容，点链接后无脚本标记、静态阶段无请求（拦截器也未收到外部请求）。新增 1 条自动用例覆盖当前表单值、画布 PNG、图片重绑和清理；画布在原 7 题中不存在，画布序列化仅由专项用例覆盖。可行性仅证实这三个内置题型和当前 Chromium；任意第三方 HTML/CSS、自定义字体、真机和正式归档均未验收，不能将探针白名单当成生产契约。

复现：`node core/scripts/dev/probe-v2-static-snapshot.mjs <playwright/index.mjs>`（本机 Chrome）。截图及逐题记录在忽略目录 `.temp/v2-static-snapshot/`。专项测试通过；Windows Checks、Ubuntu Checks、Ubuntu Performance 均通过，无失败用例（[代码头 5ad47a1 的 CI](https://github.com/lear111/quizforge_web/actions/runs/43466222741)）。
