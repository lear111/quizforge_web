# O1：打开与切换题库的端到端诊断

任务卡 O1；仅测量，等待审查。生产基线 main `1459c61`。

## 0. PR 摘要

改了什么：本报告、完整请求瀑布附表及计划进度。明确没改什么：不改生产前后端、测试、依赖、API/Bridge、规则输入、响应/状态码、题库与持久化格式，不实施优化。全部数据为合成、独立回环端口；不读真实题库，不访问部署站或 SSH，不打包、不部署、不合并。新增产品用例：无。兼容性：生产与测试文件相对基线无差异，四份标准答案未改。

## 1. 环境、场景与计时口径

Windows 11 10.0.26200 / i5-13500H / 16逻辑CPU / 16,869,351,424B RAM，Node24.13.0，真实 Chromium156.0.8078.4 headless，1440×1000/DPR1；不是独占机器。浏览器与服务在分离进程。临时 Playwright/CDP、Node加载钩子及生成物在忽略目录，不加入项目依赖。禁止外网请求。

每个规模/状态组合10个全新服务进程和全新浏览器context，顺序冷A→首次B→切回A→重新选择B（不计时）→刷新，共40次服务、160条样本。每次从合成种子复制数据，并去除生成种子时产生的校验缓存；保留真实规则和内置题型、富文本、图片与答题区，首题固定为单选；cold表示进程/应用缓存冷，不清空操作系统磁盘缓存。服务初始化本身不计入页面交互；start()已有异步runtimeWarmup，本测量没有额外等待它结束：完整环境计算记录在startup，首个请求可能等待它尚未完成的部分；该等待落入请求library。规则worker启动仍记录在实际触发它的请求。

**与需求措辞的差异及实际行为**：本main的 start() 在目录返回后自动打开首个题库，不存在可等待点击的空白首次界面，也没有“恢复上次选择”逻辑。本报告cold测导航开始（performance时间0）→自动首开A可交互，refresh同样测刷新→首个A，而不是伪造一次用户点击或声称恢复了选择；B和返回A使用实际目录按钮点击。测试刷新前实际再次选B（不计入返回A或刷新样本），刷新后观察到的仍为A；现行实现会选首个A，不能把它称为恢复B。本次不改此行为；该验收语义差异保留给审查者。

点击场景开始时刻为捕获到真实目录click；终点为openCollection结束后pane可交互且再经过3个requestAnimationFrame。冷/刷新还包括模块载入与目录获取，因此不能与仅点击的数字等同。HTTP路由只对3份JS内存响应加探针，动作/读题直连服务；Playwright路由使浏览器HTTP缓存关闭，应用pages/SDK/questions缓存保持原样。浏览器HTTP缓存热启动收益未在本报告中量出，不估计。

临时服务加载钩子包装原函数，不改函数返回值或存储；原生产文件磁盘内容不变。规则进程用临时preload在runner完成模块装载并注册stdin监听后发一条stderr计时标记，不更改规则输入/输出、环境指纹或缓存键；原权限模型保持，测试诊断唯一增量是下面明确的hook文件读取许可；只额外允许读取该测试hook文件。worker“冷启动”定义为父进程spawn调用开始→子进程ready标记的跨进程同一epoch时刻，另列纯模块执行时间；不把首题执行混入冷启动。探针开销未被精确隔离，不估算扣除。

小状态每题有极少合成笔迹，large约1.3MB（其中历史约1MB，剩余为当前状态）；均不使用真实状态文件。这是规模对照而非真实用户分布抽样。

## 2. 互不重叠的前端总耗时

单位ms，单元格“中位数 / P95”，nearest-rank P95。发生并行时按flush→question→assets→iframe→outline→overview→shell→finish→other优先级分配重叠时间；这只是统计归属，不改变执行。question计前台loadQuestion包围，含应用cache读取/重验证；后台预取不算前台题目等待；assets仅计showQuestion实际等待的页面/SDK与prepareAssets（foregroundAssets包围），不把后台预取的独立请求算成前台等待；iframe是mount→onLoad完成；finish是onLoad后收尾与稳定帧中未被更具体子段覆盖的时间；shell为导航开始至app.js主体开始执行（含宿主HTML/模块获取及依赖求值），other是其余未归类差额。各样本子段之和严格等于总耗时；中位数不能相加当作总中位数。

- 正式160样本、40个独立服务、16组各10次，首题均为q001，活动iframe恰好1个且可操作，没有题卡错误。测量记录中835个已完成fetch请求匹配到服务端ID，HTTP均200；485个原生Server-Timing请求是整轮服务诊断总数，包含未计时的刷新前切B及后台预取，不能当作160条场景中的必要请求数。
