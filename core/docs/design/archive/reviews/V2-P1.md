## 2. HTTP v2 规格

### 2.1 通用约定

所有新业务 API 位于 `/api/v2`，JSON 使用 UTF-8。沿用现有回环/LAN 身份边界、Origin/Host 校验、请求体大小限制及本机管理权限；不把密钥、任意文件路径或任意网络代理能力交给拓展 iframe。新接口不接受客户端指定数据根。除文件流与 204 外，成功返回对应表中对象；错误统一为：

```json
{"error":{"code":"QUESTION_INVALID","message":"题库「示例」中题目 q2 的 question：必须是对象。","bankId":"b_…","questionId":"q2","field":"questions.q2.question","details":{}}}
```

只含可面向用户的相对字段信息，不含绝对路径、用户目录名、题目正文、答案或内部堆栈。题库 ID 以下统一称 **bankId（本机题库实例标识）**；与作者的 `bank.json.id`（返回 `sourceId`）分开，避免导入同 UUID 两份时作答串库。标识均为不含路径的 opaque string，不能用来遍历文件。实例创建/移动的最终规则在 P5 定案；P1 合成夹具用固定唯一映射，重复 sourceId 不能静默合并。

共同模型：

- `S`（题目状态摘要）：`{questionId,status,revision,answerVersion,hasSavedAnswer,locked,resultRevision,score,maxScore,gradingStatus,hasDraft,hasInk}`。未评分 `score:null`，`maxScore` 取大纲，不接收客户端改满分。
- `Q`（题目详情）：`{bankId,snapshotId,questionId,type,extension,item,question,solution,answer,draft,ink,state:S,submission,result}`。`extension` 是宿主解析后的 `{artifactId,id,version,apiVersion,digest}`，不是客户端传文件路径。锁定前 `solution:null,result:null,submission:null`；锁定后 `submission` 为下述锁定凭证。错误题不返回半份 solution。
- `L`（锁定凭证）：`{submissionId,answerVersion,questionFingerprint}`，全部由后端生成/确定；题号、题库/考试范围也参与服务端匹配。
- `R`（结果）：`{status:"graded"|"pending"|"ungradable",score,feedback,outlineScores,reason}`；各小题为 `{id,score}`。`graded` 必须为数值；待人工/AI、无法评分不伪造零分，建议 `score:null`，终结策略见 Q4。
- `W`（写请求共有字段）：`{requestId,snapshotId,expectedRevision}`；requestId 是调用方生成的不透明幂等 ID。同一作用域重复 ID+同内容返回同一当前代际回执；不同内容 409。锁定/评分的额外前置条件见 3.3。
- `snapshotId` 是显式打开/刷新得到的题库快照令牌。普通读写只用已绑定快照；不是要求每次读取磁盘重算指纹。内容和已解析拓展工件均未变化时复用同一snapshotId；明确检测到变化才发布新代际、废止旧令牌，避免另一设备仅打开概览就让当前保存失效。旧快照提交 409 `SNAPSHOT_STALE`，不悄悄套到新题。

响应不使用公共缓存：作答、solution、评分、概览与编辑器均 `Cache-Control: no-store`；后续静态哈希文件可长期缓存。不得把打开前拿到的未锁定 304 与提交后的详情混用。P1 暂不优化条件请求；若保留 ETag，必须绑定快照、题状态、锁定代际和可见性，题目缓存不能仅以题号为键。

### 2.2 P1 核心接口（全部字段为本设计建议）

表中 B 表示 `/api/v2/banks/{bankId}`，Q 表示 `B/questions/{questionId}`。路径参数须逐段校验；请求中的 JSON `answer/draft/ink` 为原样数据，不能执行题型 schema。

| 方法、路径 | 请求字段/查询 | 成功响应字段 | 特有错误与说明 |
|---|---|---|---|
| GET `/api/v2/health` | 无 | `{apiVersion:2,phase,availableFeatures:[…]}` | 不读题库，不触发规则/环境初始化 |
| GET `/api/v2/catalog` | 无 | `{groups:[{id,name,items:[{bankId,sourceId,title,kind:"bank",availability,error}]}]}` | 扫描目录/最少元数据；坏题库以条目 error 呈现，不让整棵目录失败；不读活跃作答、不运行评分 |
| GET `B/overview` | 可选 `questionId`，必须在大纲中 | `{bank:{bankId,sourceId,title,description,features},snapshotId,outline,listening:[{id,title}],states:[S],lastQuestionId,initial:{question:Q\|null,error:null\|Error},pendingGrading:[{questionId,submission:L}]}` | **打开边界**，每次调用检查文件；初始题错误写入 initial.error，overview 仍 200。无题时 initial.question=null；无音频 URL/solution 全量预发 |
| GET `Q` | `snapshotId`；可选 `partId` 只用于前端定位 | `Q` | `QUESTION_NOT_FOUND`/`EXTENSION_NOT_FOUND`/`QUESTION_INVALID` 仅该题失败；正常模式不重新遍历文件；开发模式例外见 4.4 |
| PUT `Q/draft` | W + 可选 `answer`、`draft`；至少一个存在；显式 null 表示清空、未传表示不变（P1-2 确认是否简化） | `{state:S,answer,draft,requestId}` | D15：已锁定不能改 answer，ANSWER_LOCKED；非答案 draft 可继续保存，只改 revision。hasSavedAnswer 由显式 answer 保存决定，不能猜内容 schema |
| PUT `Q/ink` | W + `ink` | `{state:S,ink,requestId}` | D15：区外草稿笔迹不评分，锁定后仍可保存；只递增 revision，不改变答案代际和锁 |
| POST `Q/submit` | W + `answer`（最终快照） | `{state:S,submission:L,question,solution,item,extension,result:null}` | 一次原子保存并锁定；已锁定非重放 409；不运行评分、不创建规则子进程；写盘失败不得返回 solution |
| PUT `Q/result` | `{requestId,snapshotId,submission:L,expectedResultRevision,result:R,source:"grader"\|"manual"\|"ai",aiTaskId?}` | `{state:S,result:R,submission:L}` | 未锁定409；锁定版本不符409；无效数值/小题/范围422；AI 令牌不符409（P4）；不接收客户端 revision/maxScore 覆盖宿主字段 |
| POST `Q/retry` | W | `{state:S,question:Q}` | D15：新代际，清空 answer/draft/ink/结果/待评分/锁/相关回执，回未作答；历史不变，solution 再次不可见 |
| PUT `B/position` | `{questionId}` | 204 | 题号不在当前已打开大纲404；独立轻量串行器与小文件，不进作答事务，不增加题 revision；前端不 await 它再切题 |
| GET `B/position` | 无 | `{questionId:null\|string}` | 只读 v2 位置；已经删除的题返回 null，概览自行回退首题 |
| POST `B/refresh` | `{questionId?,expectedSnapshotId?}` | 与 overview 相同，另 `{changes:{clearedQuestionIds,addedQuestionIds,removedQuestionIds,activeRoundInterrupted}}` | 显式重新检查/加载；CAS 失败或写盘失败不发布半更新快照；刷新仍停本题，题已删除才选合法回退 |

`draft`、`ink` 的 32 MiB 状态文件上限与 64 MiB 内存缓存预算暂沿用现有量级作为**建议**（Q5），超过返回 413；最终单字段/请求上限须在 P1-2 开工前列为配置常量并审批，不能在实现时悄悄增大。路径 ID、requestId、revision 等宿主信封仍须验证类型/长度/安全整数，这不属于被取消的题型规则验证。相同信封字段禁止重复，解析器不接受非有限数字。

## 3. 作答状态 v2 与事务

### 3.1 新目录与格式建议

建议使用独立 `.qf-v2/`，**不读取、不枚举、不删除、不备份迁移** `.state`。新配置文件位置由新 StateLayout 显式注入，不能复用带 `.state` 默认路径的旧类。新建目录只发生运行实现时，本设计 PR 不创建它。

```text
.qf-v2/
  state/<instance-key>.json          # formatVersion:2，活跃状态和历史索引，不含轮次内容
  history/<instance-key>/<round-id>.json # P3：每轮一个不可变文件
  positions/<instance-key>.json      # {formatVersion:2,questionId}，独立原子写
  instances.json                    # v2 本机实例定位，非作者 UUID 的状态合并表
  settings/…                        # D14：全新默认值，不读取 v1 配置
  exams/<exam-id>.json               # P3：考试冻结数据、作答、截止、结果
  snapshots/…                       # P3：需要冻结的不可变资源/类型工件，待 Q9
  ai/…                              # P4：任务与凭据，任务作用域必须引用锁版本
```

P1 主状态建议示意（字段顺序也会由新标准答案锁定；`historyIndex` 在 P3 之前为空）：

```json
{
  "formatVersion": 2,
  "instanceId": "b_test",
  "revision": 1,
  "questionFingerprints": {"q1":"<64位小写十六进制SHA-256>"},
  "questions": {
    "q1": {
      "fingerprint":"<64位小写十六进制SHA-256>", "revision":1,
      "status":"drafting", "hasSavedAnswer":true,
      "answerVersion":1, "answer":{"choice":"A"},
      "draft":null, "ink":null,
      "submission":null, "resultRevision":0, "result":null,
      "receipts":[]
    }
  },
  "activeRound": null,
  "historyIndex": [],
  "receipts": []
}
```

这里 formatVersion:2 是**作答格式**；bank.json 的 formatVersion:2 是**题库格式**；新 `.qbank` 容器版本另在 Q7 确认，不混为一个版本。新状态文件只验证宿主字段的完整性、范围和关联，不拿题型 schema 重新校验原样 answer/draft/ink。

未出现过的题不必写空对象，由指纹表+宿主默认值提供 unanswered。revision/answerVersion/resultRevision 为不回绕的非负安全整数；到达上限明确拒绝，不能因 JS 精度溢出复用锁身份。submissionId 使用随机唯一 ID，重做后旧锁不可复活。sourceId 相同的两个实例各有单独状态文件。

历史按 D17 **每轮一个不可变文件**，主状态只存 `historyIndex:[{id,createdAt,closedAt,status,summary}]`，不保存轮次 questions 或 bankSnapshot。轮次文件含 `{id,status,createdAt,closedAt,interruptionReason,bankSnapshot,questions,summary}`；冻结题目 item/type、question/solution、answer/draft/ink/result、类型版本+digest。轮次结束先写不可变文件，再原子登记主状态索引；索引失败只产生无害孤儿文件，不发布悬空引用。activeRound 保存活动轮 id/参与题与锁引用，P3 再落实。考试单独 JSON 包含 `{examId,status,deadline,snapshot,questions,completion,receipts}`。P1 仅预留索引，不实现轮次落盘、历史事务或孤儿清理；P3 细化容量、不可变历史后续评分的表示与恢复。

### 3.2 每题状态机

| 状态 | 锁定 | 进入条件 | 允许的后继 |
|---|---|---|---|
| unanswered 未作答 | 否 | 没有正式 answer 保存；仅草稿笔迹可存在（不猜是否答案） | drafting、submitted-pending、unanswered（笔记保存） |
| drafting 草稿 | 否 | 显式保存 answer；即使 JSON 为空也是用户保存的答案 | drafting、unanswered（明确清 answer）、submitted-pending |
| submitted-pending 已提交待评分 | 是 | submit / completion lock / hand-in / 到时锁定持久成功 | graded、pending-review、ungradable；practice retry 可回未锁，exam 不允许 |
| graded 已评分 | 是 | 有效 graded 数值结果上报 | graded（CAS 改分）、pending-review（重新发起评分的明确动作，待 P4）、practice retry |
| pending-review 待人工或 AI 评分 | 是 | grader status pending | graded、ungradable、pending-review；practice retry |
| ungradable 无法评分 | 是 | 类型不可用/调用出错/超时的宿主终结报告 | 明确重新评分后 graded/pending-review/ungradable；practice retry |

任意状态的内容指纹变化或删除：清除此题全部活跃记录，状态重新未作答或题已不存在；历史不变。D16：完成练习/交卷时，没有保存过答案（hasSavedAnswer=false）的题由后端直接转 graded/0，不经过评分模块；平时未作答并不自动变零分。P1 不根据“看起来空”的 JSON 对象猜测是否作答。pending-review/ungradable 单列，不计入已得分，后续评分完成自动更新汇总，P3 明确历史最终化。

按 D15，答题区内的笔迹由页面写入 answer，属于答案且随提交锁定；区外 ink 不传给评分模块。已锁 answer 永不修改，但非答案 draft/ink 在所有锁定状态下均可保存（状态自循环），只递增题 revision，不改变 answerVersion、submission 或 result。retry 清空 answer、draft、ink、结果、锁定凭证与相关回执，回 unanswered，历史不变。PUT draft 是否最终收敛为 answer + 独立 ink，在 P1-2 的 reviews 决定，P1-1 不实现写入。

### 3.3 锁版本、分数、重放与故障

1. 保存 answer 改变时 answerVersion 递增；仅改草稿/笔迹不改变 answerVersion，题 revision 仍递增。submit 将最终 answer 与新的 L 一次写入，置 submitted-pending，写成功后发布新缓存、回复 solution。规则输入/输出在后端不存在。
2. result 请求须匹配题库/考试、questionId、当前 fingerprint、submissionId、answerVersion、expectedResultRevision。笔记 revision 变化不能误拒绝同一锁答案的评分。retry/内容清理后旧评分一律409，不把旧任务结果贴到新答案。
3. score 必须有限且 `0 <= score <= maxScore`；maxScore 为宿主大纲正有限数，分目标 ID 必须属于该大题，不能重复/缺必需项，单项范围有效。分目标总分用 `decimalSum` 校核，不 `parseFloat` 接受数字字符串、不默默截断越界分。`feedback/reason` 只限大小，纯数据不解释为脚本；pending/ungradable 的 null 分数等精确格式见 Q4。
4. 同 requestId 同操作/作用域/内容重放不重复计分、不重复历史；不同内容409。回执限制沿用有界机制而不是复制整份状态。**先鉴权，再检查回执代际，再重放**；retry 或内容刷新撤销旧提交凭证，旧回执不能重新透出 solution（STALE_REPLAY）。原始答案始终留在锁定状态，回执只记必要响应，不复制无关题状态。
5. 每个作用域串行写：从已冻结状态浅复制根→questions 容器→目标题→本次修改的回执/结果容器；未写子树共享且冻结。序列化/大小检查/写临时文件+fsync+原子替换成功后才替换缓存并冻结新容器。任何异常保持旧对象逐字节不变，失败后相同 ID 可重试。没有“先更新内存后尝试写盘”。
6. position 使用独立小文件与独立队列，不阻塞作答事务；同题库多设备最后写入者为准，异步失败不改变题目是否保存；前端可以提示位置未保存但不撤销已保存答案。刷新恢复哪个题库由浏览器本地保存 lastBankId，后端按题库存 lastQuestionId；跨设备“全局最后题库”不是总体设计要求。

沿用：严格 JSON 数字元数据、COW、冻结、原子替换、版本冲突、隔离作用域、有限幂等回执、失败回滚。删除：服务端 rules/score/outline 运行、答案 schema、校验缓存、运行环境指纹、v1 receipt/Java state/legacy history/upgradedCompletion/旧身份迁移适配、edit+state 联合事务日志。v2 的 completion/AI 仍需幂等凭证，但不原样搬入 v1 `finishReceipts/restartReceipts/completionReceipts/completionIntent/upgradedCompletion` 格式。

### 3.4 内容指纹清理与内存模式

对大纲引用的每道大题计算 `fingerprint({question: raw.questions[id], item}, "quizforge-bank-v2-question")`，其中 question 指 **type+question+solution 整块**，item 为所在大纲完整条目。调用现有 canonical JSON/fingerprint，写清 namespace 和黄金字节，不换成“只比较题干”。无 q 时以专门 missing 标识参与比较，避免 crash；新增/删除/内容改变都可确定。分组标题/题序不在题条目里时不进入该题指纹；如要纳入必须另批准，不能悄悄扩大清理范围。

open/refresh 对比当前 v2 状态：清变化/删题的 answer/draft/ink/result/锁/AI 绑定/该题回执；未变化逐字节保留；新题默认未答；正在进行的轮次若有题被清理则 interrupted，reason=content-changed。历史快照不重算或清理。清理候选持久化失败则打开返回 STORAGE_WRITE_FAILED，旧状态和旧快照继续有效，不把新题内容配旧答案返回。没有任何“读取旧 .state 再自动转换”的步骤。

文件树摘要检测与上述**每题内容指纹**不同：按已批准 Q10，音频表、素材字节、同版本类型代码变化只更新快照，不清活跃记录；只有 questions.<id> 整块 + 该题大纲条目决定活跃清理，不能用全树摘要清空全库。

`StateStore.memory` 使用同一 v2 状态机/锁/结果检查/COW/冻结/回执；存储适配器只改“提交到内存映射”，不假装写盘成功。临时练习与考试使用不同 scopeId，配额按每个scope已提交根的jsonBytes之和（同scope的缓存引用只计一次，跨scope共享子树按各自逻辑序列化体积计入；二进制资源快照另设预算），默认预算建议64MiB。关闭进程内存会话消失；需要可恢复的持久考试用独立考试文件，具体 session 类型由 P3 明确；不声称内存考试断电可恢复。对外可见内容与磁盘模式一致，存储 ID/时间由注入源确定，测试不得通过添加后端评分分支区别两者。

## 4. 题库读取与路径安全

### 4.1 两级结构检查

打开级：受检读取 bank.json→现有严格 parseJson→formatVersion===2→大纲数组三层与唯一 ID、二选一结构、小题局部唯一、非空 parts、正有限 maxScore→听力引用存在、路径或 http(s) 协议。基本字段 id/title/description/features 的必填/默认类型总体设计未完整列出，建议按宿主需要验证，不扩大到题型内容；待 Q5 确认最终字段表。重复 JSON 键指出 offset/line/column/field，不回显值。

单题级：只访问大纲中的题；缺 questions[id]→QUESTION_NOT_FOUND；无法唯一解析安装类型→EXTENSION_NOT_FOUND（歧义建议单独 EXTENSION_AMBIGUOUS，Q2）；question/solution 必须是非 null、非数组对象→QUESTION_INVALID。不执行 schema，不检查内容 parts 与 outline.parts 是否一致，不验证 answer，不运行 grade.js。大纲未引用的 questions 项忽略，不因其坏字段阻止打开；整体 JSON 重复键是解析错误，仍不能忽略。

错误示例：`题库「示例」中题目 q3 的 outline[1].items[0].maxScore：必须为大于 0 的有限数。` 概览初始题失败用 initial.error；独立切题用对应非200错误；批量锁定/评分逐项记录错误并继续。不向服务端上传“题型执行结果”来决定 bank.json 是否有效。

### 4.2 qf-asset 与材料读取

递归遍历被访问的大题 JSON 的字符串值，仅识别严格前缀 `qf-asset:`；前缀之后是**题库根内相对路径**。拒绝空路径、绝对/盘符/UNC、`..`、NUL/控制字符、Windows ADS/保留名、末尾点空格等平台危险路径。百分号转义政策需固定一次：建议不把 bank.json 字符串当 URL 解码，按字面相对路径解析；HTTP 路由只解码 ID 一次，不二次解码生成磁盘路径。使用现有 safeFile/checkPath/checkedStat/受检读，逐组件 realpath/符号链接/联接点检查、O_NOFOLLOW（平台支持时）、fstat、前后身份与大小上限不删。

资源句柄须绑定 instanceId+snapshot+questionId+可见分区。question 中的资源可提前显示；只在 solution 中出现的资源锁前不可枚举/读取。不能提供“相对文件名任意 GET”绕过 solution 边界；静态服务不得直接发布数据根、bank.json、.state、.qf-v2 或后台密钥文件。听力只有大纲引用过的 materialId 可取；本地按同一安全路径读并支持 Range，远程 src 给浏览器，无后端抓取、重定向代理或 SSRF。远端音频不参与哈希、不打入导出，离线直接报材料不可用。

原 v1 的 HTTPS-only/2048字符/私网字面量拒绝/64MiB整段缓存，与新设计的 http(s) 浏览器直接加载不完全相同；P1 不自行继承或放宽，见 Q7。CORS、混合内容、匿名/referrer 行为不能在没有播放器验收时声称已验证。

### 4.3 文件数上限与目录检查

保持单次受检遍历1000项目，不放宽到无限；题库文件、目录、本地资源参与打开/刷新检查，网络音频不参与；拓展与共享 SDK 检查按其已解析依赖范围进行。K2 的摘要缓存只减少重复读，不等于跨请求跳过 stat。超过上限不得一直转圈或返回内部英语。

已批准 Q6：错误中文说明“至少 1001 项，上限 1000 项”，details `{lowerBound:1001,limit:1000}`，**不是实际总数**，不进行第二次遍历。目录/文件统计与现有 walkEntries 一致，包含根项、子目录和文件。

### 4.4 检查时机与开发模式

| 操作 | 题库/资源树与拓展全检查 | 日常宿主安全检查 |
|---|---|---|
| 首次/切回题库 overview、显式 refresh、浏览器刷新后重新 open | 是，利用 K2 摘要缓存；无环境指纹或规则进程 | 授权、路径、限额、JSON、指纹清理 |
| 普通 question GET / draft / ink / submit / result / retry | 否，复用已打开快照 | 授权、快照/状态/锁版本、大小；原样数据与数值检查 |
| 资源真正读出 | 不全树重扫 | 该文件的路径安全、身份/大小与范围；不会把新路径当旧句柄 |
| 应用内编辑写 bank.json | 写前重新确认 bank.json 外部身份/内容 | CAS、受检路径、原子替换；不写状态日志 |
| 开发模式显示一道题 | 只重新检查该题所用拓展代码，必要时更新 artifactId/digest | 题库普通内容不因此逐请求重扫；GradingService 相关环境失效由 P2/P5 |

检查结果对象只读冻结，普通写不计算 contentIdentities 或 validationEnvironment；外部改动到明确 open/refresh 才进入当前快照，这是 D7 允许的变化。路径隔离、认证、受检资源读不能以“个人使用”取消。开发模式只限本机设置，哪些拓展属于开发对象、异步旧 grader 结果如何隔离要在 Q2 决定。
