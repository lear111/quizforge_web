# QuizForge Web v2 总体设计（草案）

状态：草案，待项目负责人确认。确认前不交给 Codex 实施。
基线：main `725a550` 之后，K2（#56）合并。

## 0. 已确认的决定

| 编号 | 决定 |
|---|---|
| D1 | 重做，不兼容 v1 的题库格式、拓展接口和前端宿主 |
| D2 | 去掉题目和答案的规则校验，`schema` 文件只作为说明文档，不由程序执行 |
| D3 | 评分放到前端执行；后端不再运行任何第三方代码 |
| D4 | 题目数据拆成 `question`（提交前可见）和 `solution`（提交后可见）两块，由宿主决定发送哪块 |
| D5 | 考试模式保留，交卷后统一评分；完成练习时对只保存未提交的题自动评分 |
| D6 | 以个人使用为主，局域网访问只用于本人跨设备；不防范本人伪造分数 |
| D7 | 外部修改题库或拓展文件后，不要求立即生效；打开题库、点刷新、重新加载页面时检查 |
| D8 | 前端改为 Vue 应用 |
| D9 | v1 的作答记录与历史记录都不迁移，v2 从零开始；v1 的 `.state` 目录不读取，留给用户自行删除 |
| D10 | 题库编辑器保留，范围与 v1 相同，不新增功能（见 4.11） |
| D11 | 拓展开发模式保留（见第 5 节） |
| D12 | 同一分组内允许混用不同题型，由题库作者决定 |
| D13 | 不提供第三方拓展的 v1 → v2 迁移说明；内置题型与现有题库由项目自行迁移，提供题库格式转换工具（不转换作答记录） |
| D14 | v1 的设置（AI 密钥、局域网密码等）不带入 v2，重新填写 |
| D15 | 答题区内的笔迹属于答案，一起提交、锁定并参与评分；答题区外的笔迹是草稿，不参与评分。提交后仍可写草稿，不影响已锁定的答案和分数。重做时全部清空 |
| D16 | 完成练习或交卷时未作答的题记 0 分。汇总立即生成，待评分的题先标"待评分"，评完后总分自动更新 |
| D17 | 历史每轮一个不可变文件，主状态文件只存索引 |
| D18 | `type` 中 `@` 后是题型主版本号；找不到匹配或有多个匹配都报错 |

## 1. 前后端分工

**原则**：后端只管数据和密钥，不执行第三方代码；第三方代码只在浏览器沙箱里运行。

| 后端负责 | 前端负责 |
|---|---|
| 扫描题库目录，读取 `bank.json`，做结构检查 | 界面、导航、大纲、白板 |
| 提供题目的 `question`；答案锁定后提供 `solution` | 在 iframe 里显示题目、收集作答（题型页面） |
| 保存答案、草稿、笔迹、分数、历史、考试记录 | 在沙箱后台环境里评分（题型的 `grade.js`） |
| 锁定答案：提交、交卷、考试到时 | 批量评分、待评分恢复 |
| 考试计时与到时锁定 | 组织 AI 评分的输入，并根据 AI 结果定分 |
| 调用 AI（持有 API 密钥）、导入导出、设置、局域网鉴权 | |
| 对分数做宿主层面的基本检查（数值、范围、对应的答案版本） | |

后端删除的部分：规则运行器、规则引擎、ajv、运行环境指纹、校验缓存、导入校验、基于规则的大纲计算。

## 2. 题库格式 v2

```json
{
  "formatVersion": 2,
  "id": "…",
  "title": "…",
  "description": "…",
  "features": { "history": true, "exam": true },
  "listening": {
    "L1": { "src": "audio/part1.mp3", "title": "听力材料一" },
    "L2": { "src": "https://example.com/part2.mp3", "title": "听力材料二" }
  },

  "outline": [
    {
      "title": "一、选择题",
      "items": [
        {
          "id": "q1",
          "listening": "L1",
          "parts": [
            { "id": "sub_q1", "label": "1", "maxScore": 2 },
            { "id": "sub_q2", "label": "2", "maxScore": 2 }
          ]
        },
        { "id": "q2", "listening": "L1", "label": "3", "maxScore": 2 }
      ]
    },
    {
      "title": "二、简答题",
      "items": [
        { "id": "q3", "label": "4", "maxScore": 10 }
      ]
    }
  ],

  "questions": {
    "q1": {
      "type": "quizforge.single-choice@2",
      "question": {
        "stem": { … },
        "parts": { "sub_q1": { … }, "sub_q2": { … } }
      },
      "solution": {
        "parts": { "sub_q1": { … }, "sub_q2": { … } }
      }
    },
    "q2": { "type": "…", "question": { … }, "solution": { … } },
    "q3": { "type": "…", "question": { … }, "solution": { … } }
  }
}
```

### 2.1 结构与职责

| 部分 | 谁读 | 说明 |
|---|---|---|
| 题库基本信息 `formatVersion`、`id`、`title`、`description`、`features` | 宿主 | 题库列表与功能开关 |
| `listening` | 宿主 | 全部听力材料，每段一个编号；`src` 为题库目录内的相对路径或 http(s) 链接 |
| `outline` | 宿主 | 分组、题目顺序、显示编号、满分、听力引用。打开题库时只发送这一部分和作答状态 |
| `questions` 的键 | 宿主 | 题号，与大纲中的 `id` 对应 |
| `questions.<题号>.type` | 宿主 | 题型 |
| `questions.<题号>.question` | 题型页面 | 内容格式由题型规定，宿主原样转发 |
| `questions.<题号>.solution` | 题型页面与评分模块 | 同上；锁定前绝不发出 |

### 2.2 大纲规则

- 三层：分组 → 大题 → 小题。各层都用数组表示顺序；题目内容中的 `parts` 用对象，顺序以大纲为准。
- 分组的 `title` 由作者填写，一般写题型名称，如"一、选择题"。程序不根据题型自动生成。
- 大纲中的每一项是一整道大题，是提交、锁定、评分、发送 `solution` 的最小单位。不支持单独提交小题。
- 大题二选一：
  - 没有小题：自身有 `label` 和 `maxScore`。
  - 有小题：只写 `parts`，每个小题有 `id`、`label`、`maxScore`；大题满分为小题之和。大题不另设标题。
- 小题属于所在大题，由大题的题型统一处理，不单独指定题型。
- 编号 `label` 由作者手写，程序不自动编号。
- 点击小题编号时，打开所在大题的页面并定位到该小题。
- 每道大题自成一体：`question` 与 `solution` 只能引用本题的内容、`qf-asset:` 文件和大纲中的听力，不得依赖其他题目的内容（例如"根据上一题的材料"）。多道题共用一段文字材料时，做成一道大题的多个小题。这样单独导出、复制或收藏一道题时不会缺失内容。
- 大题可写 `listening` 引用顶层的听力编号。多道题可引用同一段；切到引用同一段的题时，宿主继续播放，不重新加载。听力由宿主的播放器处理，不进入 `question`，题型页面不负责播放。

### 2.3 听力材料

- 本地文件：相对题库目录的路径，不允许越出题库目录；参与打开题库时的文件变化检查，随题库导出。
- 网络链接：仅限 http(s)，由宿主播放器在浏览器中直接加载。离线或链接失效时无法播放；不参与文件变化检查，导出时不打包。

### 2.4 题库内文件的引用

`question` 与 `solution` 中凡是指向题库目录内文件的引用（图片等），一律写成带固定前缀的字符串：

```json
"stem": { "image": "qf-asset:images/fig3.png" }
```

- 前缀之后是相对题库目录的路径，不允许越出题库目录。
- 宿主不理解题目结构，只需遍历一道题的 JSON、找出所有以 `qf-asset:` 开头的字符串，就能得到这道题用到的全部文件。导出、复制题目、检查文件变化都基于此。
- 共享富文本组件统一采用这一写法；题型文档须说明。
- 听力材料不使用此前缀，由顶层 `listening` 管理（见 2.3）。
- 听力暂不支持片段（只播放某一段），以后需要时在大纲的听力引用上扩展。

### 2.5 检查时机

**打开题库时**只检查画出大纲所必需的部分。不通过则整个题库打不开：

- 文件可以解析为 JSON，`formatVersion` 为 2。解析器遇到重复的键直接报错，并指出位置。
- 大纲结构合法：大题 `id` 全库不重复；小题 `id` 在所在大题内不重复；每道大题恰好满足"有 `label` 和 `maxScore`"或"有非空的 `parts`"之一；所有 `maxScore` 为正的有限数。
- 大纲中的每个听力引用在顶层 `listening` 中存在；本地路径不越出题库目录，网络链接只允许 http(s)。

**切到某道题时**才检查与这道题有关的部分。不通过只影响这道题，前端在题目区域报错，大纲和其他题照常：

| 情况 | 错误码 |
|---|---|
| 大纲中的题号在 `questions` 中不存在 | `QUESTION_NOT_FOUND` |
| `type` 对应的题型未安装 | `EXTENSION_NOT_FOUND` |
| `question` 或 `solution` 不是对象 | `QUESTION_INVALID` |

批量评分（完成练习、交卷）时，遇到以上情况的题标记为"无法评分"，其他题照常评分。

**不检查**：`questions` 中有、但大纲没有引用的题目（不会被访问，直接忽略）；大纲中的小题 `id` 与题目内容中 `parts` 的键是否一致（对不上时由题型页面报错）；`question` / `solution` 的内容。

错误都用明确的中文说明：哪个题库、哪道题、哪个字段、原因。文件数超过上限时同样给出原因、当前数量和上限，并结束加载状态（修复 K2 发现的问题）。

检查不通过时给出明确的中文错误：哪个题库、哪道题、哪个字段、原因。文件数超过上限时同样给出原因、当前数量和上限，并结束加载状态（修复 K2 发现的问题）。

## 3. 题型拓展接口 v2

```
extensions/<分组>/<题型>/
  manifest.json      必需：id、version、name、apiVersion: 2、入口文件
  practice.html/js/css   必需：显示与作答页面（iframe 沙箱）
  grade.js           必需：评分模块（沙箱后台环境，无界面）
  README.md          推荐：题型说明，question / solution / answer 的字段说明
  *.schema.json      可选：字段说明的机器可读形式，程序不执行
```

**题型页面**收到的上下文：

```
{ mode: "practice" | "exam" | "history",
  question, solution | null, answer, draft, result | null,
  capabilities: { canSave, canSubmit, canRetry, … } }
```

提交前 `solution` 为 `null`。页面通过 SDK 保存答案、请求提交，不自行评分。

**评分模块**由纯函数组成，不访问界面、网络或文件。加载后向宿主登记：

```js
QF.grader.register({
  grade(question, solution, answer, item) {
    // item：大纲中该题的条目（maxScore、parts 等）
    return { score, feedback, outlineScores, status: "graded" | "pending" };
  },
  // 以下只有支持 AI 评分的题型需要
  prepareAiGrading(question, solution, answer, item, target) { … },
  applyReview(question, solution, answer, item, previousResult, review) { … }
});
```

`status: "pending"` 表示需要人工或 AI 评分（如简答题）。

**题型页面沙箱**：沿用现有 iframe 沙箱与 CSP（不能联网、不能访问宿主）。

### 3.1 评分环境（GradingService）

前端用同一套评分环境处理单题提交和集中评分，保证两者结果一致。

- **一种题型一个环境**：每个环境是一个不可见的沙箱 iframe（无 `allow-same-origin`，CSP `connect-src 'none'`），只加载该题型的 `grade.js`。不同题型互不可见，不能篡改彼此的结果。
- **在后台线程中执行**：沙箱 iframe 内再开一个 Worker 实际执行评分，避免评分代码卡住页面。
- **批量调用**：宿主向环境发送一条消息，内含该题型的一批题目 `[题号, question, solution, answer, 大纲条目]`；环境逐题调用 `grade`，返回结果数组。
- **单题出错不影响其他题**：每次调用单独捕获错误，出错的题记为"无法评分"并附错误信息。
- **超时终止**：每批设时限（默认 10 秒，可配置）。超时则终止该 Worker，这一批题记为"无法评分"，环境下次使用时重建。
- **复用与回收**：环境建好后保留，空闲一段时间后回收；题型代码在本次会话中变化（开发模式、刷新）时重建。
- **并行**：不同题型的环境同时工作。

集中评分（4.5）的过程：按题型分组 → 各题型环境并行评分 → 汇总结果 → 一次请求发回后端。

## 4. 主要流程

### 4.1 打开题库

1. 前端请求概览。
2. 后端检查题库与拓展文件是否变化（K2 的摘要缓存），读取 `bank.json`，按 2.5 做打开时的检查。
3. 若题库内容与活跃作答记录不一致，按 4.1.2 清理活跃记录。
4. 后端返回：题库信息、大纲、听力列表（编号与标题）、每道大题的 `type`、每道大题的作答状态与分数、上次停留的题号，以及起始题的内容（按 4.2 的格式；起始题出错时只返回错误码，不影响概览本身）。
5. 前端画出大纲，确定起始题（4.1.1），在后台预加载本题库用到的题型代码（失败不报错，到打开对应题时再报），显示起始题。
6. 发现"已提交、待评分"的题时，按 4.6 补评。

全程不启动任何后台进程，不检查题目内容，不预加载听力。

#### 4.1.1 起始题

| 情况 | 停在哪道题 |
|---|---|
| 软件启动后首次打开该题库，且记录过上次停留的题、该题仍在大纲中 | 上次停留的题 |
| 软件启动后首次打开该题库，没有记录或该题已不在大纲中 | 大纲第一题 |
| 本次运行中从别的题库切回来 | 切走前停留的题（前端记忆） |
| 刷新页面 | 与软件启动后首次打开相同 |

上次停留的题号由后端按题库保存。前端切题时顺带通知后端，写入很轻，不经过作答记录的事务，也不影响切题速度。刷新后回到原来的题库。

#### 4.1.2 题库内容变化后的活跃记录

只处理活跃作答记录（答案、草稿、笔迹、分数、待评分状态），已形成的历史记录不受影响。

- 后端为每道大题保存内容指纹，范围是 `questions.<题号>` 整块与它在大纲中的条目。
- 打开或刷新时逐题比较：内容变化的题和已被删除的题，清除其活跃记录；未变化的题保留；新增的题为未作答。
- 进行中的一轮练习若有题被清除，该轮记为中断（沿用现有"内容已变更"中断轮次的做法）。

### 4.2 显示题目

1. 前端按大纲中的题号请求题目。
2. 后端在 `questions` 中查找；按 2.5 检查这道题，出错时返回对应错误码。
3. 返回 `question`、当前答案、草稿与笔迹、作答状态；已锁定的题再附带 `solution` 与结果。
4. 前端加载该题型（已预加载则直接使用），显示题目。
5. 该题引用了听力时，宿主此时才加载这段听力；如果下一道题引用的是同一段，继续播放，不重新加载。

### 4.3 保存草稿与笔迹

原样保存，只检查大小上限。不做格式检查。

- 答题区内的笔迹由题型页面写入 `answer`，属于答案，随提交锁定并参与评分；后端不区分 `answer` 的内部结构。
- 答题区外的笔迹单独保存为 `ink`，不进入 `answer`，不传给评分模块。
- 锁定后 `answer` 不可修改；草稿笔迹以及 `draft` 中不属于答案的部分仍可保存，只递增题目 `revision`，不改变 `answerVersion`、锁定凭证和结果。
- 重做清空 `answer`、`draft`、`ink`、结果、锁定凭证及相关回执，题目回到未作答状态；历史不变。

### 4.4 提交单题

1. 前端发送答案，后端将其保存并锁定，状态改为"已提交、待评分"，返回 `solution`。
2. 前端用该题型的评分模块评分。
3. 前端把结果发回后端。后端检查：分数为有限数、在 0 到满分之间、对应的是被锁定的那个答案版本，然后保存。
4. 评分结果为 `pending` 时，进入人工或 AI 评分。

### 4.5 完成练习、交卷

1. 后端锁定所有已保存未提交的答案，返回这些题的 `solution`。
   未保存过答案的题不经过评分模块，由后端直接记为已评分、0 分。
2. 前端按题型分组，每种题型加载一次评分模块，依次评分。
3. 一次性发回全部结果后立即生成汇总；待人工或 AI 评分及无法评分的题单独标出，不计入已得分，之后评分完成时总分自动更新。历史轮次的最终化条件在 P3 设计中落实。
4. 简答题等 `pending` 的题按设置自动发起 AI 评分。

### 4.6 待评分恢复

任何处于"已提交、待评分"的题（评分途中关闭了浏览器、考试到时由后端自动锁定）在下次打开时由前端自动补评。汇总与历史在全部题目评完后才最终形成。

### 4.7 考试

- 开始时冻结题目、题序、大纲与所用题型版本（沿用现状）。
- 作答期间不发出任何 `solution`。
- 到时或交卷：后端锁定全部答案；评分按 4.5 进行。若到时前端不在线，下次连接时按 4.6 补评。
- 交卷后：允许评分、人工与 AI 改分；禁止修改答案。

### 4.8 AI 评分

1. 前端调用评分模块的 `prepareAiGrading` 生成 AI 输入。
2. 后端用保存的 API 密钥调用 AI，任务排队与状态查询沿用现有机制。
3. 结果返回前端，调用 `applyReview` 得出新结果，再按 4.4 第 3 步保存。

### 4.9 历史

每轮保存：题目快照（宿主层字段、`question`、`solution`）、答案、结果、所用题型的版本。查看历史时按记录的题型版本加载页面。

### 4.10 收藏题目（以后实现，格式已预留）

收藏是把一道大题连同它需要的材料复制出来，与原题库彻底分离。收藏夹本身是一个 v2 题库，练习、评分、历史直接复用。

剥离一道题的步骤（全部由宿主完成，不需要理解题目内容）：

1. 复制该题在大纲中的条目（编号、满分、小题、听力引用）。
2. 复制 `questions.<题号>` 整块（`type`、`question`、`solution`）。
3. 收集材料：
   - 听力：按大纲条目的 `listening` 引用，复制顶层 `listening` 中的定义；本地音频文件一并复制。
   - 文件：遍历该题的 JSON，按 `qf-asset:` 前缀找出引用的文件并复制。
4. 改名避免冲突：分配新题号；听力编号与文件路径统一改名，并同步改写大纲条目和题目中的引用。
5. 写入收藏夹的 `outline`、`questions`、`listening` 与文件目录。
6. 可选：记录来源（原题库、原题号、收藏时间）。

收藏的题依赖对应题型拓展；题型被卸载或升级到不兼容的大版本时无法打开，与普通题库相同。是否带上原作答记录，到实现时再定。

### 4.11 题库编辑器

保持 v1 已有的功能范围，不新增功能，只改为 v2 的写法：

| 功能 | v2 中的做法 |
|---|---|
| 编辑一道题的内容 | 修改 `questions.<题号>` 中的 `question` 与 `solution`；编辑界面由题型拓展提供（`editor.*`） |
| 上传图片 | 写入题库目录，内容中写成 `qf-asset:` 引用 |
| 保存前的冲突检查 | 写入前确认 `bank.json` 未被外部修改，有冲突则拒绝并提示重新加载 |
| 单题编辑 | 有未保存修改时不能切题，须先保存或取消 |

说明：

- 大纲（编号、满分、小题、分组、顺序）、听力、题库信息不在编辑器中修改，需要时直接编辑 `bank.json`。
- v1 中可编辑的"题目标题"在 v2 中不存在（题目只有大纲中的编号），不再提供。
- 保存只写 `bank.json`，不再同时写作答记录，v1 的编辑日志删除。被修改的题的活跃作答记录按 4.1.2 自动清除。

## 5. 文件变化与刷新

- 只在打开题库、点刷新键、重新加载页面时检查题库与拓展文件；日常保存、切题不检查。
- 写入题库文件的操作（应用内编辑保存等）在写入前检查外部是否已修改，避免覆盖外部改动。
- 刷新后回到原来的题库和题目，而不是列表中的第一个题库。
- 拓展开发模式保留。开发模式下，每次打开一道题都重新检查该题所用拓展的文件，修改拓展代码后无需点刷新即可生效；普通题库不受影响。

## 6. 安全与信任

| 方面 | v2 的做法 |
|---|---|
| 第三方代码 | 只在浏览器沙箱中运行；后端不执行任何第三方代码（消除现有 Node `vm` 不是安全隔离的问题） |
| 标准答案 | 锁定答案后才发出 |
| 分数 | 由前端计算并上报；后端只做数值和范围检查。个人使用可接受，不防范本人伪造 |
| 局域网访问 | 沿用现有鉴权 |

## 7. 前端结构（Vue）

- 单一 Vue 应用为根，Pinia 管理题库目录、当前练习、设置、历史、考试状态。
- `ExtensionFrame` 组件封装题型页面 iframe；`GradingService` 管理评分模块的沙箱环境，每种题型一个，按需创建、空闲回收。
- 白板沿用现有实现，用组件包装。
- 标准 Vite 构建，文件带内容哈希、可长期缓存，按需加载设置、编辑器、AI 对话等模块。
