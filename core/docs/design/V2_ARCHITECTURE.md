# QuizForge Web v2 总体设计（草案）

状态：草案，待项目负责人确认。确认前不交给 Codex 实施。
基线：main `725a550` 之后，K2（#56）合并。

## 0. 已确认的决定

| 编号 | 决定 |
|---|---|
| D1 | 重做，不兼容 v1 的题库格式、拓展接口和前端宿主 |
| D2 | 去掉题目和答案的规则校验，`schema` 文件只作为说明文档，不由程序执行 |
| D3 | 评分放到前端执行；后端不再运行任何第三方代码 |
| D4 | 题目数据拆成 `question`（提交前可见）和 `solution`（提交后可见）两块，由宿主决定发送哪块 |
| D5 | 考试模式保留，交卷后统一评分；完成练习时对只保存未提交的题自动评分 |
| D6 | 以个人使用为主，局域网访问只用于本人跨设备；不防范本人伪造分数 |
| D7 | 外部修改题库或拓展文件后，不要求立即生效；打开题库、点刷新、重新加载页面时检查 |
| D8 | 前端改为 Vue 应用 |
| D9 | v1 的作答记录与历史记录都不迁移，v2 从零开始；v1 的 `.state` 目录不读取，留给用户自行删除 |
| D10 | 题库编辑器保留，范围与 v1 相同，不新增功能（见 4.11） |
| D11 | 拓展开发模式保留（见第 5 节） |
| D12 | 同一分组内允许混用不同题型，由题库作者决定 |
| D13 | 不提供第三方拓展的 v1 → v2 迁移说明；内置题型与现有题库由项目自行迁移，提供题库格式转换工具（不转换作答记录） |
| D14 | v1 的设置（AI 密钥、局域网密码等）不带入 v2，重新填写 |
| D15 | 答题区内的笔迹属于答案，一起提交、锁定并参与评分；答题区外的笔迹是草稿，不参与评分。提交后仍可写草稿，不影响已锁定的答案和分数。重做时全部清空 |
| D16 | 完成练习或交卷时未作答的题记 0 分。汇总立即生成，待评分的题先标"待评分"，评完后总分自动更新 |
| D17 | 历史每轮一个不可变文件，主状态文件只存索引 |
| D18 | `type` 中 `@` 后是题型主版本号；找不到匹配或有多个匹配都报错 |
| D19 | 作答记录和历史存放在题库文件夹内部的 `.qf-v2/` 目录，随文件夹一起改名、移动、复制、删除。程序不靠路径或 `id` 去匹配记录。复制出的副本带着复制时的进度，之后各记各的。导出题库时排除 `.qf-v2/` |
| D20 | 每轮历史是一个只读的题库副本：归档时把当时的 `bank.json`、作答记录和用到的拓展文件夹复制到该轮的目录里。回看时用现有的方式打开这个副本，全部锁定，只能写笔记。图片、音频不复制，只保留当时的引用；文件已不存在时该处显示"素材已不存在"。旧拓展无法运行时，大纲和分数照常显示，只是该题内容不可见。（取代此前的静态页面方案） |
| D21 | 单个题库的作答文件上限 32 MiB，超过时本次保存被拒绝，原记录保留。只是防止异常情况撑大文件的保险（实际记录最大约 1.3 MB） |
| D22 | 一轮练习分三个阶段：作答中 → 已完成（点"完成练习"）→ 已归档（点"再练一次"）。答案在提交或完成时锁定；分数在归档时锁定；草稿和白板笔记三个阶段都可以写。已完成和已归档阶段不允许单题重做。详见 4.9 |
| D23 | 归档时仍没有分数的题（待评分、无法评分）由宿主直接记 0 分，不弹提示 |
| D24 | 考试同样分三个阶段：作答 → 交卷后 → 归档。作答阶段不允许单题提交和单题重做，只能做完后一起交卷 |
| D25 | 作答文件损坏时报错，该题库无法打开，原文件保留不动，由用户自行处理 |
| D26 | 听力播放器在第 6 段实现，不提前 |
| D27 | 题库的 `bank.json` 或它用到的题型拓展文件有任何变化，就清空该题库当前这一轮的全部作答（取代原先按题清除的做法）。只在打开题库、点刷新、重新加载页面时判断（D7）。已完成的轮次和历史不受影响。图片、音频等其他文件的变化不触发。拓展开发模式下的处理在第 6 段另定 |
| D28 | 在应用内修改题库时，程序知道改了什么，只清受影响的那道题的活跃记录（作答、草稿、笔迹、分数），其他题不动，并把作答文件里的内容指纹更新为新值。新增题目、调整顺序、改题库名称和分组标题不清任何记录。其他标签页在下一次操作时被告知题库已变并重新载入，不做主动推送 |
| D29 | 后端内存里的每一种缓存都必须有上限和退出机制，不允许只进不出。已打开题库的表只保留最近使用的若干个（暂定 8 个），其余踢出；随题库缓存的作答记录一同踢出。被踢出的题库再次用到时重新读取，文件未变时对用户无感 |
| D30 | 点"完成练习"前弹一次简单确认（不列出哪些题未作答）。完成后不能撤回到作答中，只能修正主观题分数和写草稿笔记。完成后未点"再练一次"就关闭的，下次打开该题库仍显示这一轮的汇总页，不自动归档 |
| D31 | 同一道题在一轮内重做多次，只保留最后一次的作答和分数，之前各次不保存。一轮历史里每道题只有一份记录 |
| D32 | "上次的位置"记为最后一次作答所在的题：作答文件里加一个题号字段，在保存答案、草稿、提交、重做时顺带更新（白板笔迹单独存放，不更新它）。只切题不作答不记录、不写文件。下次打开题库时停在这道题 |
| D33 | 白板笔迹不放在作答文件里，每道题的笔迹单独一个文件，存于题库的 `.qf-v2/practice/ink/`（考试为 `.qf-v2/exam/ink/`，D50）。保存选项不读写任何笔迹，保存一道题的笔迹不影响其他题。依据是实测：50 道题带笔迹时，保存一次选项从约 19 毫秒升到约 473 毫秒 |
| D34 | 历史可以删除，数量不设上限 |
| D35 | 提交、重做按钮以及得分和反馈的显示由题型拓展实现，宿主提供提交和重做的接口并决定当前是否允许。作答状态由拓展精确到小题上报，宿主立即更新大纲，状态随答案一起保存。接口全文见第 3.0 节 |
| D36 | 一道题会变化的内容只有三种：答案、白板笔迹、评分。去掉"题型自带的非答案笔记"（`draft` 字段和 `getDraft`）。以后确有需要再加 |
| D37 | 每道题的 `status` 存大纲的显示状态，精确到小题：没有小题时是一个值，有小题时是"小题 id → 值"的映射。取值为 `unanswered`、`answered`、`correct`、`wrong`、`ungradable`。答没答由拓展报告，对错由宿主按得分与满分比较得出。不再单独保存 `answered`；答案是否锁定、是否已评分由提交凭证和评分结果得出，不另存。详见 [数据结构说明书](V2_DATA_STRUCTURES.md) |
| D38 | 大纲的每个格子（精确到小题）用五种颜色：未作答；已作答（含已提交但还没有分数的，包括等人工或 AI 评分）；对；错；无法评分。得满分为对，否则为错，不设"部分得分"。"无法评分"用醒目的警示色，提醒题库或拓展有问题 |
| D73 | 大纲继续只使用 D37/D38 的五种显示状态，不增加 AI 评分中、AI 评分失败、等待人工评分或人工编辑评语等状态。已提交但尚无有效分数的评分对象统一显示 `answered`；AI 评分进行中、AI 评分失败、等待人工评分、尚未评分、人工只修改评语但尚未产生/改变分数，均不改变 `answered`。AI 评分失败不得标记为 `ungradable`，应在评分结果/失败信息中保存失败原因，以便刷新后不自动重复调用且允许用户重试或人工评分。`ungradable` 只用于题目/拓展本身无法评分等非普通模型调用失败的情况。任务进行状态属于运行时任务状态，不写入 `state.json`；已提交的评分结果及必要失败信息才持久化。 |
| D74 | 用户主动触发整题 AI 重新评分时，拓展再次提交整道大题的 AI 上下文，后端重新评分该大题所有配置为 AI 评分的小题；本次 AI 结果校验通过后，覆盖这些小题此前保存的分数和评语，不因其 `source` 当前为 `manual` 而跳过。覆盖范围仅限本次 AI 评分清单；纯人工评分的小题不在 AI 清单内，不被修改。人工修改只阻止与其并发、尚未提交的旧 AI 批次，不能阻止用户之后主动发起的新 AI 重评分。 |
| D75 | AI 评分失败不等于一个有效的新评分结果。某评分对象从未有有效分数时，允许保存 `score: null` 和失败原因，`status` 保持 `answered`，重新打开不自动重复付费调用；已有有效分数或点评时，本次 AI 评分/重新评分失败不得抹掉旧的分数、点评或评分来源，原有大纲正确/错误状态不变，失败只在前端提示，不持久化本次失败原因（D76）。整题批量 AI 评分按小题逐项校验、逐项判定成功或失败；某个小题输出缺失或不合格，不影响其他小题的有效结果。只有对应小题本次评分成功并通过校验，才按 D74 覆盖该小题旧结果。 |
| D76 | 对已有有效评分对象执行 AI 重新评分失败时，保留原有分数、最终点评、评分来源和大纲状态；本次失败原因只通过当前前端提示展示，不写入 `state.json`，不新增失败历史或状态字段。只有此前没有有效分数的评分对象，才按 D75 保存 `score: null` 与失败原因，防止刷新后自动重复付费调用。 |
| D77 | 有小题的大题，其 `result.parts` 必须是完整的小题 ID 映射，包含 `outline.parts` 中的全部小题 ID，而不是只包含已评分小题。每个小题评分对象在尚未获得有效评分时允许 `score: null`；获得评分后保存分数及最终点评/来源。AI 或人工更新某个小题时，只更新对应映射项；大题总分由后端根据所有小题的评分状态汇总，不允许把缺失的小题键解释为 0 分或已评分。无小题的大题仍使用整题级评分对象。 |
| D78 | 整题 AI 批量评分仍只发起一次模型请求，但返回结果按小题 ID 独立校验、独立判定成功/失败。拓展声明的某个 AI 评分小题若在响应中缺失、格式不正确或分数不合法，该小题本次评分失败；其他小题只要各自结果合法就正常保存。失败小题若无旧有效分数，保留 `score: null` 并保存该小题失败原因；若有旧有效结果，则保留旧分数、点评和来源，失败只在当前前端提示。所有成功小题合并为一次 `state.json` 原子写入；失败小题不阻止成功小题保存。前端按小题显示成功结果或失败提示，便于用户立即定位问题。 |
| D39 | 作答文件每道题只有六个字段：`status`、`answer`、`result`、`submissionId`、`revision`、`receipts`。评分结果只有 `score`、`parts`、`message` 三项，不设状态字段；当前实现里 `message` 只在没有分数时说明原因，D61 规划在后续支持有分数时保存 AI 评语。三个版本号合并为一个；锁定凭证只留编号；请求凭据保留（幂等）并合并为一个列表；`historyIndex` 删除，第 3 段再定。全文见 [数据结构说明书](V2_DATA_STRUCTURES.md) |
| D40 | 点"完成练习"只做两件事：给所有已作答但还没评分的题评分；锁定全部作答。主观题的分数不锁定，完成后仍可修正。汇总页只显示最终得分，不做更细的统计 |
| D41 | 拓展不区分练习、考试、已完成、历史回看等场景。宿主把五个事实交给拓展（是否锁定、可否提交、可否重做、有无答案解析、有无评分结果），拓展照此显示；各场景只是这些事实的不同组合，由宿主决定并把关。接口里不设"模式"字段 |
| D42 | 完成练习后这一轮仍保存在 `state.json` 里，只在顶层记下完成时间；题目副本和历史文件到归档（点"再练一次"）时才一次生成。因此已完成但未归档的一轮仍受 D27 约束：此时改动题库或拓展会清掉这一轮，负责人已接受这一风险。"锁定"即给题目填上提交编号；完成练习时给所有尚无编号的题各填一个 |
| D43 | 程序须能运行历史里保存的旧拓展：同一版拓展接口（apiVersion）之内只增加可选项，不改变已有函数和字段的含义；拓展声明使用的公共组件版本（如富文本）须随程序长期保留 |
| D44 | 历史列表每轮只显示完成时间和得分。删除历史一次删一轮，删除前确认。点"再练一次"不弹确认 |
| D45 | 做题页里有"上一题""下一题"按钮，由宿主绘制和管理，按大纲顺序以大题为单位移动。汇总页排在最后一题之后，由宿主管理：大纲末尾有一项可以跳到它，最后一题的"下一题"也到它。"完成练习"按钮只在汇总页上；完成后同一页显示最终得分 |
| D46 | 初始阶段尽量简化：不为还没出现的需求写代码，后期有需要再加。按此精简打开题库时的检查：后端读入 `bank.json`、取出大纲、记下题号和满分，只检查"有大纲、题号不重复、满分是正数"三项；不检查格式版本、标题、编号、简介等，缺了就空着 |
| D47 | 后端用 Express。接受由此带来的启动多约 1 秒（约 0.76 秒 → 约 1.7 秒），不为此更换框架；请求耗时不受影响。第 7 段打包时若把后端合并为单文件，届时复测启动 |
| D48 | 前后端采用常见的分层目录结构。后端：`routes`、`middleware`、`controllers`、`services`、`repositories`、`utils`，位于 `core/server/v2/`。前端：`router`、`views`、`components`、`stores`、`api`、`services`、`types`、`styles`。页面切换用 Vue Router。详见 `V2_WORKFLOW.md` 第 8 节 |
| D49 | 考试有时间限制。开始时由用户填时长，程序当场算出结束时刻并存下来，之后只认这个时刻：关页面、关程序都不停表。到点自动交卷；也可以提前交卷（要确认）。交卷与"完成练习"是同一件事：锁定作答、自动评分、不归档，没评出分的主观题由用户自己评。汇总页的按钮负责归档。不做"放弃考试"。考试范围是整个题库。考试中大纲只分已作答和未作答 |
| D50 | 一个题库的练习和考试分开存放：`.qf-v2/practice/` 与 `.qf-v2/exam/`，两者内部结构相同。有 `exam/` 就是正在考试，打开题库时优先进入考试，此时这个题库没有回到练习的入口；考试归档后删除 `exam/`，回到原来的练习进度。其他题库不受影响，考试期间可以正常切换题库 |
| D51 | 不做启动时扫描，也不做后台任务。后端每次读写某个题库的考试时比对结束时刻，过了就按已锁定处理，拒绝再改答案（留 5 秒宽限，容纳到点时正在发送的最后一次保存）。评分在用户下次打开这个题库时由页面补做，随后显示汇总页 |
| D52 | 考试归档后与练习的历史放在同一个列表里，带"考试"标记并显示用时。是不是考试由该轮 `state.json` 里有没有 `exam` 一项看出，不另存标记 |
| D53 | 富文本只用于显示题干、选项、答案解析。作答不提供富文本输入：主观题用答题区（文字加手写），草稿用白板 |
| D54 | 题目里的富文本内容存为受限的 HTML 字符串，只认这一种格式，不再用树形文档。公式写 `$…$`（行内）和 `$$…$$`（独占一行），图片写 `<img src="qf-asset:路径">`。显示时由富文本组件清洗：白名单以外的标签、属性、样式一律去掉。理由：题库主要由 agent 编写，HTML 是它最熟的格式之一；排版能力接近 Word；人工用编辑器编辑时存下来的也是同一种东西。白名单见数据结构说明书 1.1 节 |
| D55 | 答题区是宿主提供的公共组件，拓展决定放在哪、放多宽。用户可以在里面打字、插入图片（拍照或选照片）、在草稿模式下手写，三样都是答案。宽度由拓展给定后固定不变；高度由出题人给初始值，写满自动加长。页面比它宽时原大小显示，比它窄时整体等比例缩小；里面的内容不重新排版。题干等其余部分照常随页面排版 |
| D56 | 作答产生的文件（插入的图片、答题区笔迹、以后的录音等）存在 `.qf-v2/practice/answer-files/<题号哈希>/`（考试为 `exam/answer-files/`），`answer` 里只写文件名。该题提交后后端拒绝再写这个文件夹；重做时删除；题库或拓展变化时随作答清空；归档时一起搬进历史。草稿笔迹仍在 `ink/`，不受锁定影响 |
| D57 | 一笔按落笔位置归属：在答题区里落笔的是答案，写出框的部分裁掉不存；在答题区外落笔的整笔是草稿。答案笔迹按答题区自身的坐标记录，由答题区组件画，练习模式下也看得见；草稿笔迹只在草稿模式下显示。橡皮擦两种都能擦，已锁定的答案笔迹除外 |
| D58 | 交给 AI 的作答是答题区按原始大小的截图，包含底图。屏幕上看到的答题区与截图一致 |

## 1. 前后端分工

**原则**：后端只管数据和密钥，不执行第三方代码；第三方代码只在浏览器沙箱里运行。

| 后端负责 | 前端负责 |
|---|---|
| 扫描题库目录，读取 `bank.json`，做结构检查 | 界面、导航、大纲、白板 |
| 提供题目的 `question`；答案锁定后提供 `solution` | 在 iframe 里显示题目、收集作答（题型页面） |
| 保存答案、草稿、笔迹、分数、历史、考试记录 | 在沙箱后台环境里评分（题型的 `grade.js`） |
| 锁定答案：提交、交卷、考试到时 | 批量评分、待评分恢复 |
| 考试计时与到时锁定 | 组织 AI 评分的输入，并根据 AI 结果定分 |
| 调用 AI（持有 API 密钥）、导入导出、设置、局域网鉴权 | |
| 对分数做宿主层面的基本检查（数值、范围、对应的答案版本） | |

后端删除的部分：规则运行器、规则引擎、ajv、运行环境指纹、校验缓存、导入校验、基于规则的大纲计算。

## 2. 题库格式 v2

```json
{
  "formatVersion": 2,
  "id": "…",
  "title": "…",
  "description": "…",
  "features": { "history": true, "exam": true },
  "listening": {
    "L1": { "src": "audio/part1.mp3", "title": "听力材料一" },
    "L2": { "src": "https://example.com/part2.mp3", "title": "听力材料二" }
  },

  "outline": [
    {
      "title": "一、选择题",
      "items": [
        {
          "id": "q1",
          "listening": "L1",
          "parts": [
            { "id": "sub_q1", "label": "1", "maxScore": 2 },
            { "id": "sub_q2", "label": "2", "maxScore": 2 }
          ]
        },
        { "id": "q2", "listening": "L1", "label": "3", "maxScore": 2 }
      ]
    },
    {
      "title": "二、简答题",
      "items": [
        { "id": "q3", "label": "4", "maxScore": 10 }
      ]
    }
  ],

  "questions": {
    "q1": {
      "type": "quizforge.single-choice@2",
      "question": {
        "stem": { … },
        "parts": { "sub_q1": { … }, "sub_q2": { … } }
      },
      "solution": {
        "parts": { "sub_q1": { … }, "sub_q2": { … } }
      }
    },
    "q2": { "type": "…", "question": { … }, "solution": { … } },
    "q3": { "type": "…", "question": { … }, "solution": { … } }
  }
}
```

### 2.1 结构与职责

| 部分 | 谁读 | 说明 |
|---|---|---|
| 题库基本信息 `formatVersion`、`id`、`title`、`description`、`features` | 宿主 | 题库列表与功能开关 |
| `listening` | 宿主 | 全部听力材料，每段一个编号；`src` 为题库目录内的相对路径或 http(s) 链接 |
| `outline` | 宿主 | 分组、题目顺序、显示编号、满分、听力引用。打开题库时只发送这一部分和作答状态 |
| `questions` 的键 | 宿主 | 题号，与大纲中的 `id` 对应 |
| `questions.<题号>.type` | 宿主 | 题型 |
| `questions.<题号>.question` | 题型页面 | 内容格式由题型规定，宿主原样转发 |
| `questions.<题号>.solution` | 题型页面与评分模块 | 同上；锁定前绝不发出 |

### 2.2 大纲规则

- 三层：分组 → 大题 → 小题。各层都用数组表示顺序；题目内容中的 `parts` 用对象，顺序以大纲为准。
- 分组的 `title` 由作者填写，一般写题型名称，如"一、选择题"。程序不根据题型自动生成。
- 大纲中的每一项是一整道大题，是提交、锁定、评分、发送 `solution` 的最小单位。不支持单独提交小题。
- 大题二选一：
  - 没有小题：自身有 `label` 和 `maxScore`。
  - 有小题：只写 `parts`，每个小题有 `id`、`label`、`maxScore`；大题满分为小题之和。大题不另设标题。
- 小题属于所在大题，由大题的题型统一处理，不单独指定题型。
- 编号 `label` 由作者手写，程序不自动编号。
- 点击小题编号时，打开所在大题的页面并定位到该小题。
- 每道大题自成一体：`question` 与 `solution` 只能引用本题的内容、`qf-asset:` 文件和大纲中的听力，不得依赖其他题目的内容（例如"根据上一题的材料"）。多道题共用一段文字材料时，做成一道大题的多个小题。这样单独导出、复制或收藏一道题时不会缺失内容。
- 大题可写 `listening` 引用顶层的听力编号。多道题可引用同一段；切到引用同一段的题时，宿主继续播放，不重新加载。听力由宿主的播放器处理，不进入 `question`，题型页面不负责播放。

### 2.3 听力材料

- 本地文件：相对题库目录的路径，不允许越出题库目录；参与打开题库时的文件变化检查，随题库导出。
- 网络链接：仅限 http(s)，由宿主播放器在浏览器中直接加载。离线或链接失效时无法播放；不参与文件变化检查，导出时不打包。

### 2.4 题库内文件的引用

`question` 与 `solution` 中凡是指向题库目录内文件的引用（图片等），一律写成带固定前缀的字符串：

```json
"stem": { "image": "qf-asset:images/fig3.png" }
```

- 前缀之后是相对题库目录的路径，不允许越出题库目录。
- 宿主不理解题目结构，只需遍历一道题的 JSON、找出所有以 `qf-asset:` 开头的字符串，就能得到这道题用到的全部文件。导出、复制题目、检查文件变化都基于此。
- 共享富文本组件统一采用这一写法；题型文档须说明。
- 听力材料不使用此前缀，由顶层 `listening` 管理（见 2.3）。
- 听力暂不支持片段（只播放某一段），以后需要时在大纲的听力引用上扩展。

### 2.5 检查时机

**打开题库时**（D46）后端把 `bank.json` 读进内存，取出 `outline`，顺着大纲记下每道大题和小题的题号与满分（后面保存、评分、算总分要用）。只做三项检查，不通过则整个题库打不开：

- 文件可以解析为 JSON（重复的键直接报错并指出位置），并且有 `outline`。
- 题号不重复：大题题号全库不重复，小题题号在所在大题内不重复。
- 满分是正的有限数。

保留这两项内容检查的原因是它们写错时不会报错，只会悄悄算错：题号重复会让两道题共用一份作答记录；满分写成文字会让总分相加变成拼接。

其余一概不检查，有就用、没有就空着：`formatVersion`、题库标题与简介、`features`、分组标题、显示编号 `label` 等。缺了的地方页面上显示为空，由制作者自行发现。听力引用到打开那道题时再检查。

**切到某道题时**才检查与这道题有关的部分。不通过只影响这道题，前端在题目区域报错，大纲和其他题照常：

| 情况 | 错误码 |
|---|---|
| 大纲中的题号在 `questions` 中不存在 | `QUESTION_NOT_FOUND` |
| `type` 对应的题型未安装 | `EXTENSION_NOT_FOUND` |
| `question` 或 `solution` 不是对象 | `QUESTION_INVALID` |

批量评分（完成练习、交卷）时，遇到以上情况的题标记为"无法评分"，其他题照常评分。

**不检查**：`questions` 中有、但大纲没有引用的题目（不会被访问，直接忽略）；大纲中的小题 `id` 与题目内容中 `parts` 的键是否一致（对不上时由题型页面报错）；`question` / `solution` 的内容。

错误都用明确的中文说明：哪个题库、哪道题、哪个字段、原因。文件数超过上限时同样给出原因、当前数量和上限，并结束加载状态（修复 K2 发现的问题）。

检查不通过时给出明确的中文错误：哪个题库、哪道题、哪个字段、原因。文件数超过上限时同样给出原因、当前数量和上限，并结束加载状态（修复 K2 发现的问题）。


### 3.0 题型页面接口（apiVersion 2，已定稿）

接口全文在 [题型拓展开发说明](../reference/V2_EXTENSIONS.md)，以那份为准，这里不重复。要点（D35）：题型负责画题目、画提交和重做按钮、显示得分和反馈、交出答案、精确到小题上报作答状态；宿主负责保存、锁定、评分调度、大纲、汇总，并决定当前是否允许提交和重做。宿主收到作答状态后立即更新大纲，状态随答案一起保存。

**评分模块**由纯函数组成，不访问界面、网络或文件。加载后向宿主登记：

```js
QF.grader.register({
  grade(question, solution, answer, item) {
    // item：大纲中该题的条目（maxScore、parts 等）
    return { score, parts }; // score / parts 由题型计算；暂不能自动评分时返回 { score: null }
  }
});
```

返回值和保存格式见 [题型拓展开发说明](../reference/V2_EXTENSIONS.md) 第 4 节与 [数据结构说明书](V2_DATA_STRUCTURES.md) 2.2 节。AI 评分遵循 D61：今后由 `grade()` 通过宿主提供的 `QF.ai.ask(...)` 请求模型；旧草案中的 `prepareAiGrading` / `applyReview` 不作为当前接口，具体实现留待第 5 段。

**题型页面沙箱**：沿用现有 iframe 沙箱与 CSP（不能联网、不能访问宿主）。

### 3.1 评分环境（GradingService）

前端用同一套评分环境处理单题提交和集中评分，保证两者结果一致。

- **一种题型一个环境**：每个环境是一个不可见的沙箱 iframe（无 `allow-same-origin`，CSP `connect-src 'none'`），只加载该题型的 `grade.js`。不同题型互不可见，不能篡改彼此的结果。
- **在后台线程中执行**：沙箱 iframe 内再开一个 Worker 实际执行评分，避免评分代码卡住页面。
- **批量调用**：宿主向环境发送一条消息，内含该题型的一批题目 `[题号, question, solution, answer, 大纲条目]`；环境逐题调用 `grade`，返回结果数组。
- **单题出错不影响其他题**：每次调用单独捕获错误，出错的题记为"无法评分"并附错误信息。
- **超时终止**：每批设时限（默认 10 秒，可配置）。超时则终止该 Worker，这一批题记为"无法评分"，环境下次使用时重建。
- **复用与回收**：环境建好后保留，空闲一段时间后回收；题型代码在本次会话中变化（开发模式、刷新）时重建。
- **并发能力与现状**：评分服务为不同拓展（`artifactId`）维护独立环境，具备同时执行的能力；但当前完成练习的调用方会依次等待各组结果。同一环境内逐题 `await grade()`，是串行计算，不等于 Vue 主线程被阻塞。

当前集中评分（4.5）的过程：按 `artifactId` 分组 → 依次调用各组评分环境 → 每组逐题评分 → 汇总结果 → 一次请求发回后端。未来如优化为跨组并行，须另行评估。

### 3.2 自动评分与人工评分的边界（D60）

- **自动评分**：单题提交与集中评分都由宿主调用独立的 `grade.js`；即使题目页面 iframe 没有打开，也能加载评分 Worker 按题型批量评分。`practice.js` 不承担批量评分。
- **等待人工评分**：主观题暂时无法自动给分时，`grade()` 明确返回 `{ score: null }`；这不是 0 分或异常。没有返回值（`undefined`）则是无效结果。当前 V2 的 `grade.js` 仍是必需文件，纯人工题型也不能省略它。
- **人工评分（待实现）**：用户在题型的 `practice.js` 页面内录入分数，由页面调用 `QF.page.grade({ score, parts, message })` 通知 Vue 宿主；不执行 `grade.js`，不让拓展自行发 HTTP 请求。宿主检查是否已提交、是否允许评分以及数值范围，再经后端校验并保存；成功后重新 `load(context)` 显示已保存的结果。已有自动评分的分数允许人工改分（D60）。
- **后端接口方案（待实现）**：优先复用 `PUT /api/v2/banks/{bankId}/questions/{questionId}/result`，在现有请求的 `source: 'grader'` 之外增加 `source: 'manual'`；保留 `snapshotId`、`requestId`、`submissionId`、`expectedRevision` 的快照、幂等、锁定与并发检查。此处是待开发协议，不代表当前 API 已接受 `manual`。
- **统一结果**：自动、人工及未来 AI 评分共用 `{ score, parts, message }` 与大纲汇总；只有成功持久化后的结果才作为页面显示的依据。当前后端对有分数的结果仍要求 `message: null`，人工备注及 AI 评语待第 5 段扩展。
- **AI 评分（后续）**：按 D61–D62 作为 `grade.js` 的异步能力，通过宿主调用后端；API 设置、批量调度、答题区截图和失败后的交互留待第 5 段，不在本次文档整理中扩充实现细节。

## 4. 主要流程

### 4.1 打开题库

1. 前端请求概览。
2. 后端检查题库与拓展文件是否变化（K2 的摘要缓存），读取 `bank.json`，按 2.5 做打开时的检查。
3. 若题库内容与活跃作答记录不一致，按 4.1.2 清理活跃记录。
4. 后端返回：题库信息、大纲、听力列表（编号与标题）、每道大题的 `type`、每道大题的作答状态与分数、上次停留的题号，以及起始题的内容（按 4.2 的格式；起始题出错时只返回错误码，不影响概览本身）。
5. 前端画出大纲，确定起始题（4.1.1），在后台预加载本题库用到的题型代码（失败不报错，到打开对应题时再报），显示起始题。
6. 发现"已提交、待评分"的题时，按 4.6 补评。

全程不启动任何后台进程，不检查题目内容，不预加载听力。

#### 4.1.1 起始题（D32）

| 情况 | 停在哪道题 |
|---|---|
| 作答文件里记有最后作答的题，且该题仍在大纲中 | 最后作答的那道题 |
| 没有作答文件、没有记录，或该题已不在大纲中 | 大纲第一题 |
| 本次运行中从别的题库切回来 | 切走前停留的题（前端内存记忆，不写文件） |
| 刷新页面 | 回到原来的题库；题目按前两行处理 |

作答文件顶层保存 `lastQuestionId`。后端在处理某道题的保存答案、草稿、提交、重做时，把它设为该题题号，随同一次写入落盘，不产生额外的写操作。评分结果的上报不更新它（补评在后台进行，不代表用户的位置）。只切题、不作答时不记录，也不创建作答文件。

#### 4.1.2 题库或拓展变化后的活跃记录（D27）

只处理当前这一轮的活跃作答（答案、草稿、笔迹、分数、待评分状态）。已完成的轮次和历史不受影响。

- **内容指纹**：由 `bank.json` 的内容和该题库用到的每个题型拓展的文件内容算出。不含题库文件夹的路径和名称，不含 `.qf-v2/`，不含图片、音频等其他文件。
- **写入**：第一次为这个题库创建作答文件时，把当时内存中所用版本的内容指纹存进作答文件。之后的保存不改它。
- **比对**：打开题库、点刷新、重新加载页面时，按磁盘上的现状重新算指纹，与作答文件里存的比较。相同则保留作答；不同则清空该题库的全部活跃作答，并提示"题库或题型已变化，本轮作答已清空"。没有作答文件时无需比对。
- 两次比对之间，程序使用内存中已载入的版本，磁盘上的修改不生效；这期间的作答在下次比对时一并清空。
- 作答文件内不再为每道题单独保存指纹；锁定凭证中的题目指纹改用内容指纹。

**应用内修改（D28，第 6 段实现）**：保存一次编辑时，同一题库的写操作排队执行，依次：核对前端所基于的题库版本 → 写入 `bank.json` → 计算新的内容指纹 → 在作答文件中删除受影响题目的条目并写入新指纹 → 更新内存中的题库。若写完 `bank.json` 后未能更新作答文件，下次打开时指纹不一致，按 D27 清空全部活跃作答。其他标签页带着旧题库版本发来的保存会被拒绝，不会写入。

### 4.2 显示题目

1. 前端按大纲中的题号请求题目。
2. 后端在 `questions` 中查找；按 2.5 检查这道题，出错时返回对应错误码。
3. 返回 `question`、当前答案、草稿与笔迹、作答状态；已锁定的题再附带 `solution` 与结果。
4. 前端加载该题型（已预加载则直接使用），显示题目。
5. 该题引用了听力时，宿主此时才加载这段听力；如果下一道题引用的是同一段，继续播放，不重新加载。

### 4.3 保存草稿与笔迹

原样保存，只检查大小上限。不做格式检查。

- 答题区内的笔迹由题型页面写入 `answer`，属于答案，随提交锁定并参与评分；后端不区分 `answer` 的内部结构。
- 答题区外的笔迹单独保存为 `ink`，不进入 `answer`，不传给评分模块。
- 锁定后 `answer` 不可修改；草稿笔迹以及 `draft` 中不属于答案的部分仍可保存，只递增题目 `revision`，不改变 `answerVersion`、锁定凭证和结果。
- 重做清空 `answer`、`draft`、`ink`、结果、锁定凭证及相关回执，题目回到未作答状态；历史不变。

### 4.4 提交单题

1. 前端发送答案，后端将其保存并锁定，状态改为"已提交、待评分"，返回 `solution`。
2. 前端用该题型的评分模块评分。
3. 前端把结果发回后端。后端检查：分数为有限数、在 0 到满分之间、对应的是被锁定的那个答案版本，然后保存。
4. 评分结果为 `pending` 时，进入人工或 AI 评分。

### 4.5 完成练习、交卷

1. 后端锁定所有已保存未提交的答案，返回这些题的 `solution`。
   未保存过答案的题不经过评分模块，由后端直接记为已评分、0 分。
2. 前端按题型分组，每种题型加载一次评分模块，依次评分。
3. 一次性发回全部结果后立即生成汇总；待人工或 AI 评分及无法评分的题单独标出，不计入已得分，之后评分完成时总分自动更新。历史轮次的最终化条件在 P3 设计中落实。
4. 简答题等 `pending` 的题按设置自动发起 AI 评分（D61–D62，属于第 5 段待实现功能；当前保留等待人工评分状态）。

### 4.6 待评分恢复

已提交且 **没有 `result`** 的题（如评分途中关闭浏览器、考试到时被后端锁定）在下次打开时由前端自动补评；已经保存 `{ score: null }` 的题属于等待人工或 AI 评分，不应无条件自动重复执行。汇总与历史在全部题目评完后才最终形成。

### 4.7 考试

考试是一轮不能单题提交和重做、带结束时刻的练习（D24、D49–D52）。除下面列出的以外，全部沿用练习的做法。

**开始。** 用户在题库里选择开始考试并填时长。后端建立 `.qf-v2/exam/`，记下开始和结束时刻。原来的练习进度留在 `.qf-v2/practice/` 不动。

**作答。** 保存答案、白板与练习相同。后端拒绝单题提交和单题重做，不发出任何 `solution`。宿主告诉拓展"不可提交、不可重做"（D41），拓展不需要知道这是考试。宿主显示倒计时。

**交卷。** 提前交卷或到点，都是执行一次"完成练习"（4.5）：锁定、评分、显示汇总页。到点时宿主先停止输入、存下最后一次，再交卷。

**过期。** 结束时刻一到，界面锁定答案；服务端为已发出的最后一次保存保留 5 秒宽限，到达宽限边界后拒绝改答案（D51）。页面没开着时没人交卷，这一轮停在"已过期、未评分"；用户下次打开这个题库时，宿主据后端返回的时间自动交卷并补评分。实现与验证见[任务 K 记录](reviews/V2-K-EXAM.md)。

**交卷后。** 与练习的"已完成"相同：可以改分数、写白板，不能改答案。汇总页的按钮把这一轮归档为一条历史，删除 `exam/`，回到练习。

**题库或拓展被改。** 与练习一样按 D27 处理，练习和考试两份作答都清空；考试随之消失，回到空白的练习。

### 4.8 AI 评分（第 5 段待设计和实现）

遵循 D61–D62：评分仍由拓展的 `grade()` 主导；需要 AI 时由拓展调用未来的 `QF.ai.ask(...)`，宿主协调后端用已保存的密钥请求模型，再由拓展确定分数与评语。当前尚未实现 `QF.ai.ask`，也未完成批量 AI 调度、答题区截图传递和设置页面的细化设计；实施时另行设计并审核，不将旧草案的 `prepareAiGrading` / `applyReview` 当作既定 API。

### 4.9 历史

一轮练习的三个阶段（D22）：

| 阶段 | 数据在哪 | 显示靠什么 |
|---|---|---|
| 作答中 | `state.json` | 现在的题库 + 现在的题型 |
| 已完成（完成练习后，分数还可修正） | `state.json`（D42） | 同上，只是全部锁定 |
| 已归档（点"再练一次"后） | `.qf-v2/rounds/<轮次>/` | 该轮目录里的题库副本和拓展副本（D20） |

**完成练习时**（D40、D42）不生成文件，只修改 `state.json`：给所有尚未提交的题填上提交编号（锁定），未作答的题直接记 0 分，顶层记下完成时间。随后宿主把已作答但未评分的题全部评完，一次上报。总分不保存，由后端把各题得分相加得出。

**归档时**（点"再练一次"）由后端完成，不需要前端逐题处理：

1. 仍没有分数的题记 0 分（D23）。
2. 新建该轮目录，复制当时的 `bank.json`、`state.json` 和用到的拓展文件夹；白板笔迹一并移入。
3. 清空当前的 `state.json`，开始新一轮。

复制全部成功后才清空当前作答；中途失败则删除未完成的目录，这一轮停留在已完成状态，可以重试。

**回看时**宿主用与做题相同的方式打开该轮目录：读其中的 `bank.json` 得到大纲和题目，读其中的 `state.json` 得到作答和分数，用其中的拓展显示题目。后端对该轮的一切答案、提交、重做、评分写入一律拒绝，只接受笔记；宿主给拓展的事实是"已锁定、不可提交、不可重做"（D41）。拓展不需要为历史写任何代码。

旧拓展无法载入时（接口不兼容或文件损坏），该题显示"题型不可用"，大纲的对错和分数照常显示，因为它们存在 `state.json` 里。

各阶段允许的操作（D22）：

| | 作答中 | 已完成 | 已归档 |
|---|---|---|---|
| 在哪看 | 练习页 | 练习页（带最终得分） | 只在历史记录里 |
| 改答案 | 提交前可以 | 不能 | 不能 |
| 单题重做 | 可以（考试不可以，D24） | 不能 | 不能 |
| 单题提交 | 可以（考试不可以，D24） | — | — |
| 改分数（人工、AI） | 已提交的题可以 | 可以，总分随之更新 | 不能 |
| 白板笔记 | 可以 | 可以 | 可以 |

历史可以删除，数量不设上限（D34）。考试的"交卷后"对应"已完成"，其余相同（D24）。表中的 `state.json` 指 `.qf-v2/practice/state.json` 或 `.qf-v2/exam/state.json`（D50）。

### 4.10 收藏题目（以后实现，格式已预留）

收藏是把一道大题连同它需要的材料复制出来，与原题库彻底分离。收藏夹本身是一个 v2 题库，练习、评分、历史直接复用。

剥离一道题的步骤（全部由宿主完成，不需要理解题目内容）：

1. 复制该题在大纲中的条目（编号、满分、小题、听力引用）。
2. 复制 `questions.<题号>` 整块（`type`、`question`、`solution`）。
3. 收集材料：
   - 听力：按大纲条目的 `listening` 引用，复制顶层 `listening` 中的定义；本地音频文件一并复制。
   - 文件：遍历该题的 JSON，按 `qf-asset:` 前缀找出引用的文件并复制。
4. 改名避免冲突：分配新题号；听力编号与文件路径统一改名，并同步改写大纲条目和题目中的引用。
5. 写入收藏夹的 `outline`、`questions`、`listening` 与文件目录。
6. 可选：记录来源（原题库、原题号、收藏时间）。

收藏的题依赖对应题型拓展；题型被卸载或升级到不兼容的大版本时无法打开，与普通题库相同。是否带上原作答记录，到实现时再定。

### 4.11 题库编辑器

保持 v1 已有的功能范围，不新增功能，只改为 v2 的写法：

| 功能 | v2 中的做法 |
|---|---|
| 编辑一道题的内容 | 修改 `questions.<题号>` 中的 `question` 与 `solution`；编辑界面由题型拓展提供（`editor.*`） |
| 上传图片 | 写入题库目录，内容中写成 `qf-asset:` 引用 |
| 保存前的冲突检查 | 写入前确认 `bank.json` 未被外部修改，有冲突则拒绝并提示重新加载 |
| 单题编辑 | 有未保存修改时不能切题，须先保存或取消 |

说明：

- 大纲（编号、满分、小题、分组、顺序）、听力、题库信息不在编辑器中修改，需要时直接编辑 `bank.json`。
- v1 中可编辑的"题目标题"在 v2 中不存在（题目只有大纲中的编号），不再提供。
- 保存只写 `bank.json`，不再同时写作答记录，v1 的编辑日志删除。被修改的题的活跃作答记录按 4.1.2 自动清除。

## 5. 文件变化与刷新

- 只在打开题库、点刷新键、重新加载页面时检查题库与拓展文件；日常保存、切题不检查。
- 写入题库文件的操作（应用内编辑保存等）在写入前检查外部是否已修改，避免覆盖外部改动。
- 刷新后回到原来的题库和题目，而不是列表中的第一个题库。
- 拓展开发模式保留。开发模式下，每次打开一道题都重新检查该题所用拓展的文件，修改拓展代码后无需点刷新即可生效；普通题库不受影响。

## 6. 安全与信任

| 方面 | v2 的做法 |
|---|---|
| 第三方代码 | 只在浏览器沙箱中运行；后端不执行任何第三方代码（消除现有 Node `vm` 不是安全隔离的问题） |
| 标准答案 | 锁定答案后才发出 |
| 分数 | 由前端计算并上报；后端只做数值和范围检查。个人使用可接受，不防范本人伪造 |
| 局域网访问 | 沿用现有鉴权 |

## 7. 前端结构（Vue）

- 单一 Vue 应用为根，Pinia 管理题库目录、当前练习、设置、历史、考试状态。
- `ExtensionFrame` 组件封装题型页面 iframe；`GradingService` 管理评分模块的沙箱环境，每种题型一个，按需创建、空闲回收。
- 白板沿用现有实现，用组件包装。
- 标准 Vite 构建，文件带内容哈希、可长期缓存，按需加载设置、编辑器、AI 对话等模块。
