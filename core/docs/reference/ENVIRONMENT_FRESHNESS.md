# 规则运行环境的变更检测

写入前的环境复查采用七文件哨兵和最长 10 分钟的成功指纹复用；题库内容检查及读题的 30 秒策略独立保留。B2a 的实现与测量依据见 [审查记录](../design/reviews/B2a.md)。

| 输入或触发 | 写入前的保证 |
|---|---|
| bank.json、题库材料/资产、拓展目录及相关配置 | contentIdentity/contentIdentities 每次即时执行，原方法不改。变化后按原加载/拒绝流程处理。普通 POST 的前置读绑定检查也保留。 |
| process.execPath、server/rules-runner.cjs、ajv/fast-uri/fast-deep-equal/json-schema-traverse/require-from-string 各自的 package.json | 暖写对七个文件各取一次 FileCache 相同的文件身份，任一变化、缺失或检查失败立即全量计算，本次写入使用全量结果。 |
| 上述依赖包中的其他文件，且七个哨兵保持相同身份 | 可复用上一次成功完整环境指纹；超过 600,000 ms 的第一次写入重新完整计算。因此这类变化最多延迟到窗口到期后的第一次写入才由写路径发现。其他完整计算可更早发现变化。 |
| 启动首次使用、冷加载、导入、显式 invalidate | 保留完整计算；冷加载后的第一次写入还会强制完整计算，随后才进入暖写复用。invalidate 清除缓存与代际；导入的隔离校验仍完整复查，安装后使目标库失效。 |
| unavailable | 不缓存为可复用的成功值。哨兵无法通过受检读取时也不建立成功缓存；完整计算的结果沿用原处理方式。 |

文件身份精确沿用 FileCache 的 `dev、ino、size、mtimeNs、ctimeNs、birthtimeNs`。哨兵使用原 `fileIdentity → checkedStat → statIdentity`，保留普通文件、符号链接、重定向路径检查；暖路径每文件一次 lstat，共七次，不递归依赖目录。完整计算前后核对哨兵，变化时不发布复用缓存；进行中的完整计算不能跨 invalidate 代际重新发布旧缓存。

窗口从完整计算开始时记起。恰好 600,000 ms 仍可在哨兵一致时复用，600,001 ms 则完整计算；检测到时钟回退也强制重算。时间通过 `Library.now` 注入，测试不实际等待。这里的“10 分钟”是环境缓存时限，不是后台轮询周期；没有写入或其他完整检查时，不主动扫描磁盘。

读路径 `runtimeEnvironment()` 仍按原先 30 秒复用最近一次完整指纹；暖写命中不刷新这个读 TTL。因此带前置读检查的 HTTP 写请求，也可能在 30 秒读 TTL 到期时提前完整计算并发现非哨兵变化，不能理解为这类变化必须等满 10 分钟。读写没有统一成同一缓存规则。

完整指纹仍由原 `RuleEngine.validationEnvironment()` 按原文件列表、内容、排序、namespace 生成；哨兵身份只是复用条件，不拼入环境指纹，不修改校验缓存键或版本号。已有有效校验缓存不因此整体失效。

这是缓存新鲜度保证的有意调整，**不是新的安全边界**。运行环境指纹用于判断已验证题库/规则的缓存是否过期，不认证安装文件的可信作者，也不提供原子文件系统快照或阻止拥有本机安装目录写权限的人。修改七个哨兵或依赖文件需要既有本机文件权限；本次不授予这些权限，不改变拓展的 Node 子进程权限、iframe/Bridge、网络权限或目录受检读取。对题库内容和拓展文件的即时复查同样不放宽。生产更新仍应使用正常应用更新/重启，不应把此缓存当作防恶意篡改的机制。
